## 第 1 步实现范围

- 电费工具独立使用 `electricity.db`，其他工具以后拥有自己的数据库。
- `electricity_bill` 保存月份、总金额、总用量、时间与备注。
- `electricity_share` 保存当月每户的名称、稳定电表标识、本人标记、读数、用量与金额快照。
- 月份唯一；删除账单时使用外键级联删除明细。
- 账单和全部明细通过一个 Room 事务写入。
- 写入前校验月份、本人数量、连续顺序、稳定标识、读数、用量和金额合计，避免保存内部不一致的数据。
- DAO 已预留按 ID、月份、上一期和月份倒序查询，为后续第 2、3、6 步提供基础。
- Room schema 从版本 1 开始导出，未使用 `fallbackToDestructiveMigration`。

## 第 1 步动态验收

在安装 Android SDK 37、JDK 17 并启动模拟器或连接真机后执行：

```powershell
.\gradlew.bat :feature:electricity:test
.\gradlew.bat :feature:electricity:connectedDebugAndroidTest
.\gradlew.bat :app:assembleDebug
```

动态验收通过后，提交 `feature/electricity/schemas` 下由 Room 生成的版本 1 JSON schema，并确认第 1、2 步的本机持久化基础可用。

## 第 2 步实现范围

- 使用 `ElectricityBillRepository` 隔离 ViewModel 与 Room，计算页面不直接访问 DAO。
- 应用级组合根创建并复用数据库，未引入不必要的依赖注入框架。
- “保存本月账单”把账单主表和全部分摊快照写入同一个事务。
- 保存期间锁定表单、增删户数、返回和页签切换，防止重复提交或保存过程中修改数据。
- 保存成功后显示明确状态并清除“未保存”标记，返回时不再弹出放弃确认。
- 相同月份不会静默覆盖已有账单，而是保留当前表单并提示到记录页面修改。
- 数据库或其他异常会显示错误，表单数据不会被清空，用户可以重试。
- 修复计算页返回按钮无效以及趋势页返回行为与文字不一致的问题。

第 2 步与第 1 步共需执行：

```powershell
.\gradlew.bat :feature:electricity:test
.\gradlew.bat :feature:electricity:connectedDebugAndroidTest
.\gradlew.bat :app:assembleDebug
```

## 第 3 步实现范围

- 历史页通过 Repository 订阅 Room `Flow`，保存新账单后列表可自动更新。
- 账单按 `YYYY-MM` 从近到远排列，不按创建时间误排序。
- 每张记录展示月份、本人费用、总电费、总用量和分摊户数。
- 页面包含加载、无记录和读取失败三种完整状态；读取失败支持重试。
- 空状态的“去计算电费”按钮会返回真实计算页面。
- 历史数据只从 Room 读取，不包含硬编码演示记录。

## 第 4 步实现范围

- 历史记录卡片可进入账单详情，查看总电费、总用量、本人费用及每户读数、用量、占比和分摊金额。
- 详情页订阅指定账单的 Room `Flow`，修改完成后返回时会显示最新数据。
- 修改页复用经过校验的计算表单，回填原月份、总电费、电表名称、本人标记和读数快照。
- 修改保存使用单个 Room 事务更新账单并替换全部明细；任何一步失败都会整体回滚。
- 修改月份时继续执行唯一性检查，不会覆盖另一月份的账单；原创建时间与备注会保留。
- `updatedAt` 在设备时钟回拨时也不会倒退，为后续备份与排序保留稳定语义。
- 删除前必须二次确认；删除主账单后由外键级联删除全部分摊明细。
- 详情读取失败、记录不存在和删除失败均有明确提示；失败不会伪装成成功离开页面。

## 第 5 步实现范围

- 趋势页订阅现有 Room 历史摘要，新增、修改或删除账单后会自动刷新。
- 每个月只读取标记为本人的分摊金额，不把总电费或其他住户费用混入趋势。
- 展示最新费用、全部记录的平均费用与最高费用，并计算相对上次已保存账单的金额和百分比变化。
- 上次费用为 0 时不计算无意义的无限百分比，但仍展示实际变化金额。
- 使用 Compose Canvas 自绘最近 12 条账单，不增加第三方图表库；月份间有缺口时不伪造数据，也不跨缺口连线。
- 图表提供可读的无障碍说明，页面同时保留全部月份的倒序明细列表。
- 完整覆盖加载、空记录、单条记录和读取失败重试状态。

## 第 6 步实现范围

- 新建账单时按当前所选月份精确查询上一个自然月，不会用更早的旧账单冒充上月数据。
- 找到上月账单后恢复全部电表的稳定标识、名称、顺序和本人标记，并将上月本期读数作为本月上期读数。
- 持久化校验明确要求第一条明细必须是本人电表，为后续 JSON 恢复继续守住“第一列固定为我”的约定。
- 本月本期读数保持为空，仍需用户实际抄表后填写，不会生成虚假用量。
- 修改历史账单时不执行自动带入，确保编辑页面忠实显示原始快照。
- 月份切换会取消旧查询并校验结果月份，防止较慢查询覆盖新月份表单。
- 用户开始修改读数、增户或删户时立即取消自动查询；已手动输入的数据不会被后台结果覆盖。
- 页面明确显示读取中、带入来源、上月无账单和读取失败状态；失败时可重试或直接手动填写。
- Room 查询严格使用 `billingMonth.minusMonths(1)`，并有数据库测试验证缺月时返回空结果。

## 第 7 步实现范围

- `core:backup` 定义与业务字段无关的 `BackupContributor` 契约，每个工具独立导出、检查和恢复自己的数据。
- 电费备份使用带格式版本、工具 ID、数据版本和导出时间的 UTF-8 JSON，完整保存账单及每户快照。
- 使用与 Kotlin 2.3 系列匹配的 Kotlinx Serialization 1.11.0；序列化实现只存在于电费模块，核心契约不携带 JSON 依赖。
- 通过 Android Storage Access Framework 选择保存位置和备份文件，不申请存储目录权限。
- 文件限制为 5 MB、1200 个月、每月 20 户，并限制 JSON 嵌套、文本和数值长度。
- 选中文件后先检查格式、工具 ID、版本、重复月份、本人位置、读数、用量和金额合计，再显示恢复确认。
- 只有二次确认后才替换数据；Room 在一个事务中删除当前电费记录并写入全部备份，失败时整体回滚。
- 恢复只影响电费工具，其他工具的本地数据不受影响；数据库主键重新生成，月份和电表稳定标识保持不变。
- 历史页始终提供“数据导出与恢复”入口，即使当前没有任何账单也可以导入。
- 备份格式与恢复规则记录在 `BACKUP_FORMAT.md`。

## 第 8 步实现范围

- 数据管理页增加独立 CSV 导出入口，继续使用 Android 系统文件选择器选择保存位置。
- CSV 只用于表格查看和分析，不提供导入能力；可还原的数据迁移继续使用 JSON。
- 账单按月份升序，每月每户各占一行，包含总金额、总用量、户序号、电表标识、名称、本人标记、读数、用量、分摊金额、备注和时间。
- 文件使用 UTF-8 BOM、CRLF 和标准双引号转义，改善 Windows Excel 中文兼容性。
- 金额固定输出两位小数，读数保留原始十进制精度，时间使用 ISO-8601 UTC。
- 文本字段检测 `= + - @` 和控制字符，并增加文本前缀，降低 CSV 公式注入风险。
- 空数据库仍可导出只有表头的有效 CSV；导出编码器和 ViewModel 均有单元测试，Room 集成覆盖 Android 数据库测试。
- 字段与安全规则记录在 `CSV_EXPORT.md`。
