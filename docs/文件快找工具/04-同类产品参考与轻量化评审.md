# 文件快找 · 同类产品参考与轻量化评审

日期：2026-10-30；初版：产品草案 0.2；本轮同步至复核版 0.3。

依据：用户要求从专业产品设计和日常使用习惯出发，参考同类产品，突出离线、便捷、边界清晰、简单、好用和体积小。本文建议尚未经过用户原型验收。

下文保留0.2的轻量化取舍；0.3补齐首次通用查找、并发请求、交付保护与阶段准入，详见 [05](05-设计复核与阶段准入.md)，具体流程以同步修订的01—03为准。

## 1. 本轮结论

将产品定位收敛为：**聊天文件接得住，异常安装包能识别，旧文件容易找。**

最常用路径应是“QQ 的用其他软件打开 → 随身工具箱 → 安装 → 系统确认”。工具自己的首页服务于找旧文件和再次使用；从聊天进入时直接处理当前文件。

相较 0.1 草案，本轮作以下修订，01—03 已同步：

| 原建议 | 本轮建议 | 原因 |
| --- | --- | --- |
| 查找 / 最近两个底部页签 | 一个首页，内嵌最近使用；全部记录用轻量列表展开 | 降低导航层级，入口少但可找回旧文件 |
| 首屏四种分类与多个筛选 | 首屏仅安装包 / 全部；更多筛选按需展开 | 用户最常找的是刚收到的安装包 |
| 正常包“安装”、异常包“整理并安装” | 已识别支持的 APK 统一“安装”，说明自动整理名称、保留原件 | 用户任务是安装；命名由工具处理 |
| 生成副本后长期保留至手动清理 | 普通任务副本短期保留；重要文件由用户另存到手机 | 避免处理几十个安装包后占用不断增长 |
| 小主要是页面少 | 同时控制 APK 增量、运行负担、索引和副本占用 | 界面简单不等于存储占用小 |

文件名搜索、通用文件入口、异常后缀查找、最近记录、来源范围和失败处理仍属首版范围；仅减少常驻界面与非必要操作，不取消原始需求。

## 2. 调研方式与证据边界

本轮于 2026-10-30 查阅开发者官方仓库、README、发布记录及 Google 官方帮助；未在手机安装这些软件，未进行红米 K60 / QQ 的操作对比，也未测量它们的包大小、耗电、速度或联网行为。

下表“可借鉴”是基于公开功能说明形成的设计判断，不是用户实测结论。没有充分官方依据的 `.apk.1`、QQ 候选列表、当前机型兼容性均不打“支持”勾。部分产品具有网络或高级安装能力，不能将其整体称为纯离线软件。

## 4. 从用户习惯反推设计

### 场景 A：刚在 QQ 收到安装包

用户已经定位到文件，只希望尽快安装。重新选择分类、查找目录、填写输出名都不应成为前置步骤。

建议流程：

1. 在 QQ 的外部打开列表选择随身工具箱。
2. 工具自动读取、识别，显示图标、应用名、版本、文件名和大小。
3. 用户点“安装”；必要的复制与文件名整理在后台完成，并展示准备进度。
4. 进入系统确认；完成或取消后可直接返回 QQ。

首次安装来源授权是系统步骤，单独统计；后续有效授权下，工具内仅需一次“安装”点击。点选工具箱只表示打开文件，不视为已经同意安装。

不默认设为所有文件的打开应用，也不要求设为默认浏览器。通过当前入口是否能选到工具箱，仍以 QQ 实测为准。

### 场景 B：已经下载过，过一会儿想安装

首页先展示最近使用的少量文件；文件未处理过时，点击“查找安装包”。找到结果后按最近修改时间排序，未知时间置后。搜索框过滤已索引结果，不每输入一个字就重新扫描手机。

无结果时先区分筛选过窄和范围不足，再给出“查看全部类型”“扩大查找”“选择文件”。不在首屏展示长篇系统限制说明。

### 场景 C：偶尔收到一个普通文件

“选择文件”保留全部类型，“全部”支持名称搜索。正常文档可交给其他应用打开；格式未知时允许另存并说明暂不支持。不为了少见格式在首屏增加一排分类或内置阅读器。

### 场景 D：装完就走，很久后再用

返回时保留列表位置；下次进入无需登录、联网、重新做引导或先清理手机。副本若已到期清理，“最近”仍说明状态并提供重新选择。用户需永久保留的文件使用“另存到手机”。

## 5. 页面收敛

正式页面仅保留三个层级：工具首页、当前文件详情、范围与空间管理。最近全部记录可用底部面板，不增加常驻底部导航。

首页默认状态示意：

```text
← 文件快找                              ⋮

[ 搜索已找到的文件                       ]

[ 查找安装包 ]                  选择文件

最近使用                         查看全部
图标  随身工具箱 · 1.2.0               ›
      multi-tools-v1.2.0.apk.1
      副本可用（暂存）· 125 MB

图标  example.apk                      ›
      48 MB · 需要重新选择

仅查找已授权的位置                 查看范围
```

点击搜索或查找即进入同页查找状态，在首次扫描之前、零结果时也显示安装包 / 全部；可以直接查普通文件。扫描统一索引范围内普通文件的必要元信息，类型与关键词只影响展示。近期使用可通过右上角菜单返回；查找状态返回上一步恢复首页最近区，首页再返回工具箱。普通列表点击进入详情，避免一触即启动安装。

详情默认只放：图标、应用名、版本、文件名、大小、状态和“安装”。异常名称下方用一句“会自动整理文件名，原文件保留”。原始与输出文件名、包名、最低版本和哈希等按需展开。

范围授权、另存、分享、全部最近记录和副本管理保留可发现入口；不与主按钮争夺首屏空间。

## 6. 六条产品原则与验收

| 原则 | 产品规则 | 验收方式 |
| --- | --- | --- |
| 离线 | 查找、识别、整理和请求安装均在本机；不增加联网权限、账号或服务依赖 | 文件已在本地、处于飞行模式且其他条件具备时完成主要流程；核对合并 Manifest |
| 便捷 | 从 QQ 直达文件详情；正常与异常命名共用“安装” | 有效授权后仅一次工具内安装点击；返回不重新选文件 |
| 边界清晰 | 明确当前访问范围，格式判断与安装结果准确 | 私有目录不可读不谎报找到；解析成功不冒充安装成功 |
| 简单 | 一个首页、两个主要入口、单个主按钮 | 首次无需学习术语、设模式或走教程 |
| 好用 | 有效反馈、可取消、失效可恢复、原件保留 | 权限拒绝、空间不足、安装取消、未知结果均有下一步 |
| 小 | 控制功能增量、后台活动和临时占用 | 对照基线测量包增量与存储；扫描和解析均可中止 |

离线边界：QQ 下载、云盘取文件、系统可能进行的安全检查属于外部环节，不能由工具箱保证全程断网可用。验收使用已完整下载到本机的文件。

## 7. “小”的具体预算

以下为建议的工程预算，尚未实测，不是对当前或最终包大小的承诺：

- **包体积**：新增文件快找能力使同条件正式 APK 增量目标不超过 2 MiB。沿用现有 Compose、Room 和平台接口；新依赖需要说明用途和实际体积。
- **运行负担**：不新增常驻进程、自动后台扫盘或轮询。只有用户查找或处理文件时工作；打开工具箱首页不顺带启动扫描。
- **数据量**：不为所有文件保留完整图标、内容或历史版本；最近元信息最多保留 20 条，首页先显示 5 条，其他走展开列表。
- **副本空间**：普通任务副本默认在最近使用 7 天后具备清理资格，暂存软预算 512 MiB。进入工具或开始新任务时检查；不为到点清理启动后台服务。
- **清理条件**：先保护当前详情 / 任务文件，仅回收无使用占用的任务副本；优先已过期副本，空间压力下按最近使用顺序清理。未知安装结果与交付占用分开判断；不能确认外部使用结束时不自动回收，按02的F09提供用户明确结束的管理出口。界面说明为“最近副本可能被清理”，并提供另存；剩余时间不是永久保留保证。
- **大包例外**：512 MiB 是暂存预算而非 APK 文件格式上限；单个任务超过预算但设备空间足够时允许处理，显示实际占用，不因软预算直接排除大包。受保护文件可暂超预算；空间评估包括系统安装暂存等同时存在的副本，空间不足则停止新任务，不抢删使用中的文件。
- **保留边界**：用户主动另存的外部文件永久性由其存储位置决定，本工具不自动删除；原聊天文件和用户原件始终不因副本回收而受影响。

期限、条数和预算沿用0.2建议值，待真实样本确认后在开发规格中冻结；首版无需为此增加复杂设置页。处理中的副本绝不因超期、超预算或历史记录被移除而删除；系统自行回收缓存或卸载造成的失效需如实展示，不承诺暂存永久可靠。

工具箱已有健身离线图片，“这个工具增加得少”与“整个工具箱安装包很小”需要分开衡量。包体积对比必须在相同构建方式、资源和 ABI 条件下进行，不能拿测试包与正式包直接相减。

## 8. 必须保留、按需呈现与延期

| 首版必须有 | 首屏按需呈现 | 后续再评估 |
| --- | --- | --- |
| QQ 外部打开 / 分享与手动选择 | 完整位置与范围授权 | 收藏与多版本对比 |
| APK 及数字尾缀候选识别 | 复制、另存、分享 | 分包 / 批量安装 |
| 稳定副本与系统安装 | 包名 / 哈希等详细信息 | 其他格式的异常后缀处理 |
| 文件名搜索、安装包 / 全部 | 更多筛选和所有最近记录 | 全文 / AI 搜索 |
| 最近使用与副本回收 | 副本空间与手动清理 | 远程存储、内置阅读器 |
| 权限和失败返回、原件保护 | 一屏内解释当前失败原因 | 自动后台查找 |

## 9. 下一阶段与新增验收

第一优先是红米 K60 上验证 QQ 外部打开，不先建设完整扫描器。微信入口、系统选择文件和目录查找依次补齐验证；所有来源受同一隐私和副本规则约束。

原型新增 U15—U18：

- U15：单首页的最近 / 结果切换、全部最近面板与返回位置。
- U16：正常 APK 和 `.apk.1` 均一个“安装”按钮，异常名称自动处理且说明清楚。
- U17：飞行模式、本地已下载文件、无登录和无网络等待。
- U18：副本到期或因空间预算回收后，记录仍可理解；原件、外部另存文件和进行中任务不受影响。

正式开发前另记录：包体积基线、冷启动和首次结果耗时、不同大小 APK 的准备耗时、索引规模和副本占用。均采用可重复条件测量，不预先宣传“秒装”“全盘搜全”或“完全不占空间”。

0.3另补U19—U24：首次通用查找、完整覆盖标记、多请求隔离、清理保护、重启与授权失效、工具箱自身更新。完整清单及阶段放行条件以02、03为准；其中QQ直接打开的三关不能用手动选择文件替代验收。
