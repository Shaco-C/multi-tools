# 文件快找 · 产品需求与交互设计

日期：2026-10-29；修订：2026-10-30；版本：设计复核版 0.3。已确认背景见 [README](README.md)，轻量化取舍见 [04](04-同类产品参考与轻量化评审.md)，本轮复核与阶段准入见 [05](05-设计复核与阶段准入.md)。文档复核不代表原型或真机验收通过。

## 1. 产品目标

用户收到安装包后，不需要了解手机目录结构，也不需要先学习修改扩展名，就能找到文件、识别内容并交给系统安装。用户再次使用同一文件时，可以从最近处理记录直接进入。

三个体验目标：

- **找得到**：普通 `.apk` 和异常后缀候选都能在实际可访问范围内出现；范围外的内容有明确的导入路径。
- **看得懂**：展示应用名称、版本、原始文件名和可用状态，避免同名文件选错。
- **用得上**：已确认的 APK 可直接请求安装，异常名称可生成正确后缀副本；失败后有针对性的下一步。

文件为什么变成 `.apk.1` 尚未实测。重名处理、传输端命名、未完成下载都可能影响名称或内容，产品不直接断言是 QQ / 微信修改了文件。

## 2. 首版范围和优先级

| 优先级 | 功能 | 用户收益与范围 |
| --- | --- | --- |
| P0 | 快速查找与范围管理 | 搜索已授权目录和已导入文件；针对当前 APK 分发渠道验证可选广泛访问能力，解决反复翻目录的问题 |
| P0 | APK 与异常后缀候选识别 | `.apk`、`.apk.1`、`.apk.2`、重复数字尾缀、大小写变体；支持手动送入未知名称文件 |
| P0 | QQ / 微信外部打开或分享接收 | 发送端支持且授予可读 URI 时，直接到文件详情；找不到分享入口时仍可手动选择 |
| P0 | 系统选择文件 | 不只筛选 APK MIME，保留全部可选择文件，避免 `.apk.1` 被隐藏 |
| P0 | 文件详情与安装 | 读取 APK 信息，用户点“安装”后自动准备副本与整理名称，按需申请安装来源权限并交给系统；原文件保持不变 |
| P0 | 最近处理与副本管理 | 再次打开、再次安装、另存、重新分享；显示副本是否仍可用 |
| P0 | 通用文件搜索 | 在同一可访问范围内按文件名查找，首屏仅安装包 / 全部；其他格式交给外部应用打开 |
| P0 | 完整失败与恢复流程 | 取消授权、找不到、文件失效、空间不足、安装返回不明确、进程退出等均有可解释结果 |
| P1 | 常用文件与同包归组 | 收藏、多个版本对比、按内容哈希识别相同副本，保留各自位置 |
| P1 | 更多类型的异常后缀处理 | 逐类验证 PDF、图片、Office 文档、压缩包的识别规则，不把所有 ZIP 都当成 APK / DOCX |
| P1 | 批量整理与导出 | 展示每个文件的成功 / 失败；逐项处理，不批量静默安装 |
| P2 | 自动刷新与更丰富搜索 | 增量扫描、桌面快捷入口、经验证后的后台任务；先评估电量和系统限制 |

首版不包含：聊天记录读取、全盘内容全文搜索、文件恢复、杀毒、系统清理、自动删除原文件、静默安装、分包安装器、压缩包解压与合并分卷。XAPK / APKM / APKS 只做识别提示，不列为可直接安装的单 APK。

## 3. 三条核心使用路径

### 3.1 已下载过，但不知道存在哪里

工具箱 → 文件快找 → 查找安装包 → 结果 → 文件详情 → 安装（按需自动整理名称）。

- 首页默认最近使用；进入查找时先显示已有索引及上次查找时间，再按用户操作刷新，避免每次进入都重新等待扫描。
- 首次进入不要求完成授权向导；保留“选择文件”。用户主动查找但没有范围时，再提供授权位置与直接选择的入口；扩大访问在范围管理中按需开启，不伪造扫描进度。
- 快速查找优先覆盖实际可读的下载位置、用户添加的文件夹和经过实测的公开聊天保存位置。
- 扩大查找由用户主动触发，搜索更多可访问共享目录；不扫描应用私有数据，也不承诺找全手机文件。
- 扫描边进行边显示结果，允许停止；停止后保留已找到项，标记“查找未完成”。

### 3.2 当前就在 QQ / 微信文件页面

用户已明确要求的主要路径：

**QQ 中打开 `xxx.apk.1` → 用其他软件打开 → 选择随身工具箱 → 自动识别并展示应用信息 → 安装（自动整理文件名）→ 系统确认安装。**

产品目标是直接作为文件处理应用出现在候选列表，不要求用户为这一步额外下载浏览器，也不要求先打开工具箱扫描或修改文件名。入口显示工具箱名称和图标；具体选择器显示样式由系统或 QQ 决定，测试版必须与正式版可区分。

“用其他软件打开”和“分享给其他应用”需要分别接入、分别验收，不能只做分享接收就认定前者可用。微信同类路径随后验证，实际菜单名称以当前版本为准。

接收 QQ 授予读取权的单个文件 URI 时，这条路径不依赖先开启广泛文件访问；只有用户另外使用扫描能力时才按需处理范围授权。首次请求安装时仍可能需要系统的安装来源授权。

当前 v1.2.0 尚无对应接收入口，需要安装加入此功能的新版本后才具备参与候选列表匹配的能力。工具箱尚未安装时，不能由自己处理自身的首次安装包。

是否能显示在当前 QQ 列表中，要区分系统文件打开选择器与 QQ 自建的推荐 / 限定列表。前者可通过声明文件处理能力参与匹配；若当前页面限定了应用或指定了浏览器，本工具不能强制插入，需验证是否可进入系统更多应用或分享入口。不能仅因已有浏览器能打开就承诺任何第三方工具都一定被列出。

若发送端不提供可读文件，只传网页或文本，则显示“没有收到可读取的文件”，引导先下载、保存或手动选择；不把网页链接当本地 APK。

外部进入时直接显示该文件，不先绕到工具箱首页。返回优先回到来源页面，保持工具箱内已有页面状态。手机上同时安装测试版与正式版时，接收入口需能区分。

### 3.3 已经处理过同一个安装包

文件快找首页最近使用 → 文件详情 → 安装 / 另存 / 分享。

“最近”表示本工具处理记录，不能叫“最近收到的聊天文件”。聊天接收时间和来源应用只有在可可靠确认时才展示，不能由文件夹名字推断。

## 4. 信息架构与页面

```text
随身工具箱
└─ 文件快找
   ├─ 首页
   │  ├─ 查找安装包 / 选择文件
   │  ├─ 最近使用（默认状态）/ 查找结果（查找后状态）
   │  ├─ 搜索与查找状态：安装包 / 全部、范围与刷新
   │  └─ 全部最近记录（展开面板）
   ├─ 文件详情 → 准备进度 → 系统安装 / 保存 / 外部打开
   └─ 范围与管理
      ├─ 当前查找范围 / 添加目录 / 权限状态
      ├─ 应用内副本与占用空间
      └─ 清理记录 / 使用说明
```

使用一个首页，不设置底部导航。首页默认展示最近使用；查找后切换为同页结果状态。首版常用筛选只有安装包 / 全部；文档、压缩包、图片和音视频均可在“全部”中按名称查找，更细分类按需放入后续版本。

### 4.1 查找首页

页面示意，数量与文件均为原型示例：

```text
← 文件快找                                   ⋮

[ 搜索已找到的文件                            ]

[ 查找安装包 ]                          选择文件

最近使用                               查看全部

图标  随身工具箱  1.2.0
      multi-tools-v1.2.0.apk.1
      副本可用（暂存）· 125 MB                  ›

图标  example.apk
      48 MB · 需要重新选择                     ›

仅查找已授权的位置                     查看范围
```

- 点击搜索框或查找按钮即进入同页查找状态，立即显示安装包 / 全部，即使尚未扫描或结果为零也可切换；不将首页最近记录和大量结果叠成长列表。最近入口仍可通过菜单找到。
- 默认“安装包”，用户切换“全部”后按钮相应显示“查找文件”；从外部打开文件不受上次筛选限制。
- 搜索文件名，不强制先选分类。搜索提示“搜索已找到的文件”；没有索引时显示“尚未查找此范围”，提供“查找文件 / 选择文件”，不能写成“没有该文件”。首次找 PDF 不必先完成一次 APK 查找。
- 同一次范围扫描枚举所有可访问普通文件的轻量元信息，不读取所有文件内容；安装包 / 全部仅影响显示，APK 名称规则仅决定候选。切换类型复用索引，不隐式重新扫描。关键词、类型和时间筛选不能影响来源扫描完成标记；达到索引上限时按部分完成展示，阈值在技术规格中确定。
- 支持应用名称和包名搜索，但只覆盖已经识别的 APK；提示尚未识别项需继续读取，不承诺首次扫文件名就知道所有应用名。
- 默认按修改时间倒序，未知时间置后，稳定并列排序。近 24 小时 / 7 天按修改时间筛选，时间未知提供独立选项；不将修改时间写成接收时间。
- 高级筛选收起：查找位置、文件大小、后缀需整理、待识别 / 已识别。首屏只放常用项。
- 后缀异常是一种待处理状态，不能直接用危险或病毒标识。
- 长文件名优先保留结尾 `.apk.1`，详情可查看和复制完整名称。
- “当前范围找到 8 个文件”和“查找到一半得到 8 个文件”必须区别展示；分类计数仅表示已索引结果。

### 4.2 文件详情

上半部显示识别结果：图标、应用名、版本、文件状态；随后显示原始文件名、大小。完整位置或“由其他应用提供”、最后修改时间、包名、最低系统版本、SHA-256 等进入折叠详情，取得可靠值才显示。

默认优先呈现图标、应用名、版本、文件名、大小、状态和主按钮；完整位置与修改时间在详情展开后查看。每个状态只保留一个明确主操作。

主按钮随状态变化：

| 当前状态 | 主按钮 | 附近说明 |
| --- | --- | --- |
| 读取 / 识别中 | 禁用并显示处理进度 | 可取消；不自动开始安装 |
| 已识别普通 APK | 安装 | 调用系统安装器，由用户继续确认 |
| 已识别且名称异常 | 安装 | 自动整理文件名并生成副本，原文件保留 |
| 已识别的普通文档等 | 用其他应用打开 | 由设备上支持该格式的应用处理 |
| 无法识别 / 读取失败 | 重新选择或重试 | 显示具体可确认的问题，保留原始信息 |
| 疑似分包 / 特殊安装集合 | 查看说明 | 首版不支持合并安装，可另存原文件 |

次要操作为“另存到手机”“分享文件”“复制文件名”，折叠到更多操作；首版不提供修改原件和删除原件。

只有暂存副本可用时，在状态下直接显示“副本可能被清理，需长期保留可另存”及另存入口，不将这一信息只藏在管理页。只有 APK 候选或用户主动要求识别的未知文件才进入包解析；正常文档只展示文件信息，不默认为了打开文档完整复制大文件。临时授权无法满足再次使用时，说明暂存需要并展示进度。

“安装”一次点击同时授权必要的副本准备和安装请求；正常包和异常名称共用该按钮。异常名称下方说明“会自动整理文件名，原文件保留”，无需再选择处理模式、填写文件名或弹一个重复说明的确认框。首次安装来源授权、系统安装确认由系统处理。整理后的字节内容不变，只改变文件名和打开方式；不修改 APK 包名、签名或代码。

### 4.3 最近

- 首页显示最近 5 条，查看全部时展开最多 20 条元信息记录；该条数为草案建议，技术验证后冻结。
- 按本工具最近操作时间排序，显示“已识别”“副本可用”“已请求安装”“安装结果未确认”等准确状态。
- 搜索命中、普通扫描不会把全部文件塞入最近；用户实际打开详情、导入或处理后才记录。
- 点击再次使用前重新检查访问状态。原文件消失但本工具副本还在时，仍可使用副本。
- 记录不等于文件：清除记录不删外部文件；移除应用内副本需单独操作，并显示预计释放空间。
- 无安装结果回执时，不把用户从安装器返回直接标成“安装成功”。
- “最近”保留的是使用记录，不承诺永久保存文件内容；副本按第7节期限与空间规则回收，失效时保留重新选择入口。

### 4.4 范围与管理

每个来源显示名称、真实访问状态、上次扫描时间、已索引数量；移除目录授权同时停止对该来源的查找，并使引用项变为需重新授权。已有应用内副本仍保留。

三种状态分开：可访问、需要重新授权、系统限制不可访问。系统禁止的目录不能反复弹授权框诱导用户重试。

“扩大查找”解释为允许读取更多共享文件；只在用户使用此能力时请求权限。回到应用后重新检查实际结果，拒绝后提供其他入口。

## 5. 文件识别与命名规则

| 文件例子 | 首版行为 |
| --- | --- |
| `tool.apk` / `tool.APK` | APK 候选，继续识别 |
| `tool.apk.1` / `tool.apk.2` / `tool.apk.1.1` | 异常尾缀候选，识别成功后才允许整理 |
| `tool.apk.001` | 疑似编号或分片，不能直接认定为完整 APK；经内容检查确认后再决定 |
| `tool.apk.zip` / `tool.apk.bak` / 无扩展名 | 首版不遍历打开所有未知文件；“全部”可找到，用户选入后尝试识别 |
| `notes.apk.txt` | 不凭名称中的 `.apk` 就加入已确认安装包 |
| `tool.apks` / `tool.xapk` / `tool.apkm` | 特殊集合候选，不作为普通单 APK 自动安装 |
| 只有 `PK` 文件头的 ZIP | 只能说明可能是 ZIP，不能说明是 APK |

候选发现依靠文件名和提供方元信息；内容确认依靠可读的稳定副本与 Android 包信息解析，必要时检查容器结构。识别失败不等于文件必然损坏，也可能是不支持、读取被拒绝或内容未传完整。`getPackageArchiveInfo` 可能返回空；获取到包信息也不等于可独立安装或已验证安全。[Android 包信息接口](https://developer.android.com/reference/android/content/pm/PackageManager#getPackageArchiveInfo(java.lang.String,int))

命名建议：

- 已确认 `multi-tools-v1.2.0.apk.1` 的输出建议为 `multi-tools-v1.2.0.apk`，版本名称与原有主体不擅自改写。
- 碰到已有同名文件，生成 `multi-tools-v1.2.0 (1).apk`，序号放扩展名前，不覆盖已有文件。
- 无法生成合适主体时，用 `应用名_版本.apk`，清理路径分隔符、控制字符等非法名称内容。
- 同名不同内容必须保留；同包名同版本也不等于同内容。只有内容哈希一致才能确认字节相同。
- 系统另存提供方可能调整名称，应展示最终返回的实际名称与位置；不能假定写入名与建议名完全一致。

## 6. 查找范围与 Android 约束

普通模式覆盖用户选入的文件、允许授权的目录及本工具保存的副本。增强模式在用户授权后扩大共享存储查找范围；仍无法读取其他应用的私有数据，包括被系统限制的 `Android/data` 区域。[所有文件访问说明](https://developer.android.com/training/data-storage/manage-all-files)

Android 11 及以上，系统目录授权不能直接授予整个内部存储根目录或整个 `Download` 目录。可选文件和可授权文件夹是两种能力，页面不能简单提示“授权整个下载目录即可”。[系统文件选择器的限制](https://developer.android.com/training/data-storage/shared/documents-files)

因此，**快速扫描和聊天导入必须同时存在**。若目标文件只存在于 QQ / 微信私有区域，实际可用路径取决于该软件是否支持外部打开、系统分享、另存或文档提供方暴露；全部不支持时，应明确说明当前无法读取，建议在发送端重新以可保存的文件形式提供。

首版按现有 GitHub APK 渠道验证扩大访问能力。若未来上架 Google Play，广泛文件访问和安装权限均需按核心功能要求分别评估，不能因新增一个文件工具就默认符合。也不能承诺删掉一个权限后所有体验保持一致。[文件访问政策](https://support.google.com/googleplay/android-developer/answer/10467955)、[安装权限政策](https://support.google.com/googleplay/android-developer/answer/12085295)

## 7. 副本、隐私与生命周期

- 扫描默认只读取名称、大小、时间等必要元信息；APK 图标与详情按需读取，避免首次扫描逐个完整解析大包。
- 分享或选择文件可能只带临时授权。需要跨会话再使用时，先在授权有效期间保存应用内副本；能持久授权时也要允许后续失效。
- 普通范围索引只保存引用。详情解析时的临时文件、整理后的可复用副本、用户另存的外部文件必须分开管理。
- 区分任务暂存与用户永久另存。普通任务副本采用受控暂存：默认最近使用7天后可回收，软预算512 MiB，进入工具或开始任务时清理，无后台定时任务；空间压力下可按最近使用顺序提前回收无占用副本，最近记录需明确“副本可能被清理”。具体默认值为草案建议，见04。
- 用户主动“另存到手机”的外部文件不纳入自动回收；希望长期保留时明确引导另存。应用内任务副本和详情临时文件不是永久文件仓库。
- 大文件处理先显示可获得的大小与所需空间，缺少大小则边读取边检查上限，允许取消；不把整包读入内存。
- 管理页显示本工具副本总占用、可清理与受保护空间；开始详情读取、复制、导出或安装前先保护当前副本，再执行回收。安装结果与文件交付占用分开记录，不能仅因结果未知永久占用，也不能因返回页面就释放。可靠交付结束后恢复普通暂存规则；结束条件无法确认时保留保护，提供明确说明的“结束外部使用并清理”，不得自动删除。规则见02的F09与03的交付验证。
- 单个大包不因软预算直接拒绝，按实际剩余空间和任务上限判断；受保护文件可暂时超过软预算，空间不够则明确失败。空间估算包括应用副本、导出和系统安装暂存，不能只计算一份 APK。
- 退出、崩溃或被系统回收后，未完成临时文件不能显示成已完成副本；下次进入显示“上次处理已中断”，提供重试。外部交付状态需先恢复核对，不因进程重启清空保护标记；如被系统清掉缓存，则记录实际失效，不承诺暂存绝不丢失。
- 卸载工具箱会移除应用内副本和记录。重要文件使用“另存到手机”；外部导出文件不受本工具的清理操作影响。
- 首版不增加联网权限、服务器或统计 SDK，不读取聊天消息。云盘提供方可能自行联网取文件，应用不能承诺其云端文件在离线时可用。
- 文件目录和聊天文件名不写入普通诊断日志，不默认打包进现有账单、饮食或健身备份。文件引用和 URI 授权无法简单随备份迁移。

## 8. UI 规范与易用性

沿用 `core:designsystem` 的 Material 3、深蓝文字、青绿色强调色、浅底色和约 20dp 卡片圆角，跟随清爽 / 暖白 / 纯白主题。页面横向间距参照现有 18dp，主操作触控目标不少于 48dp，并验证大字体。

优先显示文件与可执行操作，权限技术名放帮助说明。详情底部一个主按钮，加载时防重复触发。状态同时使用文字和图标，不仅依赖颜色。

操作后返回保留查询、分类、范围和滚动位置。系统授权返回保留当前文件；不能让用户重新从目录找起。列表不提供左右滑动即删除，以免误删记录或文件。

首版不增加趋势图、打卡或安装排行榜。对用户有价值的数字是“找到多少文件”“范围是否完整”“副本占多少空间”。

轻量化同时衡量包体增量、运行负担与临时存储。新增功能对同条件正式APK的增量目标不超过2 MiB，属于待构建验证的预算；不新增常驻扫描、内置阅读器或远程文件系统。完整取舍和测量口径见04。

## 9. 产品成功指标

以下为验收目标，不是已取得的测试结果：

- 已有有效权限、文件已识别时，从列表到请求系统安装不超过两次应用内点击；从QQ直达详情后仅一次“安装”点击。系统授权与确认步骤单独统计。
- 候选测试集中所有已纳入规则的异常尾缀均被找到；普通 ZIP 和文本不会被标记为已确认 APK。
- 快速查找支持边找边看和随时停止；耗时以固定设备、目录规模和 APK 大小测量，不预先承诺全盘几秒完成。
- 任何失败或取消都不删除、覆盖、改写用户原文件；保留必要的重新选择 / 重试路径。
- 最近记录能区分原文件可用、副本可用、授权失效和安装结果未知。
- 核心方案必须在红米 K60 的 QQ、微信各完成一次真实的“接收 → 找到 / 导入 → 整理 → 系统安装”流程，记录不可达路径。

详细验收与下一阶段顺序分别见 [02](02-流程状态与验收清单.md) 和 [03](03-技术可行性与阶段计划.md)。
