# 文件快找 · 设计复核与阶段准入

日期：2026-10-30；版本：0.3。范围为产品设计包，未实现或发布文件快找功能。

## 1. 复核结论

**本轮文档层面的矛盾和关键遗漏已补齐，可以入库，并进入可达性验证与通用页面原型准备。当前不能宣称 QQ 兼容、自动回收、安装结果回执或包体预算已经验证通过。**

复核按用户的实际任务展开：QQ收到文件、直接打开、找旧文件、找到文档、识别异常名称、安装、再次使用、失败恢复和清理。另行进行独立文档复核，重点交叉检查01的产品承诺、02的状态与验收、03的阶段出口和04的轻量化取舍。

保留首版方向：离线、一个首页、单文件处理、原件不变、统一“安装”按钮、默认简单。没有追加分包安装、批量队列、后台服务、内容阅读器或网络功能。

## 3. 本轮发现与修订

以下“已修订”指规则和文档完成，不代表对应代码或测试完成。

| 问题 | 可能造成的体验或实现漏洞 | 本轮修订 | 对应验收 |
| --- | --- | --- | --- |
| 通用文件入口出现太晚 | 首次找PDF被迫先查APK，零APK误以为没有文件 | 激活搜索即显示安装包 / 全部，未扫描与无匹配分开 | U19 |
| 索引覆盖与类型筛选不明确 | 切换全部出现假空，关键词未命中旧项被标为删除 | 统一枚举轻量元信息，筛选只影响展示，部分扫描不更新完整覆盖 | U20 |
| 新外部请求没有忙碌规则 | A安装授权返回后误安装B，或覆盖当前副本 | 单任务、操作与文件身份绑定、最多一个暂挂请求，不能复用旧安装意图 | U21 |
| 未知安装结果与文件占用混合 | 回到页面立即误删，或长期无法回收 | 独立保护状态；当前详情先保护再回收；交付可靠结束才自动释放，不明时提供明确结束出口 | U22—U23 |
| 自身更新造成进程结束未覆盖 | 任务丢失、重复安装、误报成功 | 安装前持久化，更新后恢复，不自动重发，不凭版本变化推定本次成功 | U24 |
| 阶段A与C都写“最小链路”，且出口过宽 | 不清楚何时做验证程序；手动选文件被误算QQ指定入口通过 | A是隔离能力验证，C才正式接入；QQ三关独立放行，微信另验有效路径 | 03第5节 |
| 详情层级、缓存和文档状态表述有冲突 | 核心信息过多，清理承诺不清，入库被误解为已实现 | 详情次要信息折叠、暂存另存提示可见、受保护空间与系统暂存分别核算、统一0.3状态 | U14、U18、U22 |

额外明确：普通文档不默认全量复制并尝试APK解析；一次扫描有容量与取消边界；原件失效与副本失效分开；共享结束没有可靠信号时，不用任意超时猜测安全回收。

## 5. 下一阶段的执行顺序

1. **准备验证包。** 整理普通APK、数字尾缀、同名不同内容、截断包、普通ZIP、文档与大文件的样本说明，准备设备记录表。使用公开或构造样本，不提交用户聊天文件或原始URI。
2. **做最小能力验证。** 在具备Android环境的电脑生成隔离验证程序，在红米K60走QQ三关；随后验证微信与手动选择。比较安装交付方式，验证保护解除和结果回执，不先建设完整扫描器。
3. **并行准备通用原型。** 完成最近 / 查找、首次全部类型、详情、范围、失败、并发请求、暂存管理；权限和系统动作标为模拟。真机发现约束后回填原型，再做U01—U24验收。
4. **冻结首版开发规格。** 以能力证据和原型验收为前提，确定访问模式、MIME接收、数据对象、操作状态、资源上限、恢复与清理规则。若QQ核心入口被限制，先明确未满足项并与用户确认调整承诺。
5. **进入正式实现。** 按03的C—E阶段：独立工具接入 → 单文件与安装 → 外部入口 → 来源索引与搜索 → 最近与空间管理 → 端到端验证及发布。已有验证结论复用，正式代码遵循项目现有模块与依赖习惯。

本次授权交付为文档复核和远程入库。下一阶段的程序、原型及设备操作在后续任务中执行；本次没有把产品设计任务扩大为Android功能开发。
