# 饮食不适记录：原生 Android 实施

确认范围：只记录不适饮食；品牌与品牌下的食品集中维护；不适类型可维护、默认腹泻；进食日期精确到日，不适自动记录到时分；多次不适关联同一顿饮食；品牌／食品明细、柱状图、类型与时间筛选。

- [x] 2. 记录页、新建／追加、撤销、修改、结束与恢复本次记录。
- [x] 3. 品牌、食品、不适类型管理及明细、柱状图。

数据单独保存到 diet.db，不修改现有电费数据库。正式应用不预置示例饮食。停用不删除历史，改名按 ID 保持统计关联。只收集不适记录，不计算发生率或诊断原因。

新增 APK 使用原发布密钥，版本 1.1.0 / versionCode 2。构建环境与缓存继续使用 D 盘。

## 使用流程

1. 从工具箱打开“饮食不适记录”。先到“管理”添加品牌（例如麦当劳）及品牌下的食品（例如辣翅）。不适类型预置腹泻、胃痛、恶心，可以改名、新增、停用和设置默认类型。
2. 出现不适时点击“记录一次不适”，选择品牌、食品和不适类型。进食日期默认昨天，可以快捷选择今天、昨天、前天或日历；备注选填。首次发生时间取打开记录表单的时刻，保存前不会写入数据库。
3. 同一顿饮食继续出现不适，点击“再记一次腹泻”（或当前默认类型），自动记录点击时的日期与时分。每次保存后可以撤销；时间线也支持修改、删除。
4. 这顿饮食不再需要追加时，点击“结束本次记录”。以后又吃了同一种食品，需要新建饮食；历史记录可明确恢复后继续追加。
5. 点餐前到“品牌”搜索并查看食品明细。“统计”显示带数字的品牌横向柱状图；三次不适关联一顿饮食时，两个统计口径分别显示 3 次与 1 顿。筛选按不适发生日期计算，点击柱状图保留当前筛选进入明细。
6. “管理”底部独立导出饮食 JSON 备份 / CSV。恢复会先校验，再显示记录数量，确认后仅替换饮食工具数据。电费备份和电费数据库不受影响。

## 实现要点

- 模块路径：`android_app/feature/diet`；导航入口：`tools/diet`。
- Room 规范化存储、外键约束、事务写入；仅更新发生变化的行，输入文字和切换表单字段不写数据库。
- 饮食与不适事件分开保存；撤销操作只影响目标事件，保留之后新增的事件和改名操作。
- 记录 UTC 毫秒时间及当时的时区偏移，避免换时区后历史日期变化。
- JSON 严格校验工具标识、版本、ID、关联、日期、时区、名称、数量和 5 MB 大小上限；无效文件不会替换数据。CSV 包含全部事件、时区和备注，处理引号、换行及表格公式前缀。
- 不新增网络 / 存储权限；文件操作使用 Android 系统文件选择器。Android 12 及以上同时显式排除系统云备份和设备迁移，换机请分别导出各工具备份。规则依据 [Android 官方备份说明](https://developer.android.com/identity/data/autobackup)。
- 数据库测试采用 [Robolectric](https://robolectric.org/getting-started/) 的 Android 9 / 15 本地环境，依赖与下载锁保存在 D 盘 Gradle 缓存。另提供可在手机或模拟器上执行的 Room instrumentation 测试。

## 手机验收建议

- 安装后检查原有电费账单和背景主题仍保留。
- 首次打开饮食工具没有示例饮食；维护“麦当劳 / 辣翅”，保存昨天进食、今天不适，再追加两次。品牌与食品应为 3 次不适，关联 1 顿饮食。
- 修改一条事件时间、删除并撤销，检查时间线与统计同步更新。
- 修改品牌名、停用食品，检查历史仍在，新建选项隐藏，重新启用后能再次选择。
- 结束本次记录、再新建同食品的饮食，检查关联饮食计数为 2；恢复旧记录可以继续追加。
- 导出 JSON / CSV，先保留当前备份，再确认恢复，检查饮食记录与电费账单相互独立。
- 在系统深色模式、较大字体、软键盘弹出和横屏下检查可读性、滚动与按钮操作。
