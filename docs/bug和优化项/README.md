# Bug 和优化项

按计划交付的小版本统一归档Bug和优化项，方便后续集中安排修复、实现、验证和整理发布说明。

## 版本目录

| 计划版本 | 说明 | 事项清单 |
| --- | --- | --- |
| 1.2.1 | 基于正式版1.2.0的Bug修复与体验优化批次，尚未发布 | [1.2.1 Bug和优化项清单](1.2.1/README.md) |

## 记录约定

- 每个事项单独一份文档，版本索引标明类型为Bug或优化项。
- Bug编号采用 `BUG-版本号-序号`，例如 `BUG-1.2.1-001`；优化项采用 `OPT-版本号-序号`，例如 `OPT-1.2.1-001`，两类分别编号。
- 目录名代表计划交付版本，不表示事项已经完成，也不直接修改应用版本号。
- Bug记录受影响版本、实际表现、复现步骤、预期行为、影响、分析依据、修复建议和验收项。
- 优化项记录现有体验、优化目标、使用场景、实现范围、方案建议和验收项。
- 用户反馈、源码静态分析、运行复现和修复验证分别注明；尚未验证的根因保留为待确认。
- Bug状态依次为待修复、修复中、待验证、已关闭；优化项依次为待实现、实现中、待验证、已关闭。完成后补充实际方案、提交记录和验证结果。
- 调整计划版本时同步更新事项索引，保留原编号与调整说明，避免重复登记同一事项。
