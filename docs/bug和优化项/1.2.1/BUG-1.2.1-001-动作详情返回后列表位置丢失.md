## 1. 问题表现与影响

创建训练计划时，用户按部位浏览动作，向下滚动后点击动作图片进入详情。返回动作选择界面时，列表回到顶部，未停留在刚才的位置，用户需要再次向下查找。

动作较多或连续查看多个动作时，反复找回浏览位置会打断选择流程。这里的“返回顶部”指列表滚动位置丢失；当前源码中的返回目标仍是动作选择页，尚无证据表明计划草稿或已选动作因此丢失。

## 2. 复现步骤

1. 打开居家健身工具，创建计划并进入选择动作步骤。
2. 为某个训练日期选择部位，进入该部位的动作选择列表。
3. 向下滚动，使列表顶部离开屏幕；记录当前可见动作及其屏幕位置。
4. 点击其中一个动作的图片进入详情，并浏览详情内容。
5. 返回动作选择列表，观察原动作的位置是否保持。

用户报告的实际结果：返回后列表回到顶部，需要手动向下滚动。具体设备构建、筛选条件、是否加载更多以及使用哪一种返回入口，运行复现时补充记录。

## 3. 预期行为

- 同一选择上下文中查看详情再返回，恢复离开前的动作位置及屏幕内偏移，避免先显示顶部再滚动跳转。
- 当前训练日期、部位、搜索词、器械与来源筛选、仅看已选状态、已加载数量和勾选结果保持。
- 在详情中加入动作后返回，只更新选中状态与数量，浏览位置继续保持。
- 主动改变部位、搜索或筛选属于结果集变化，可按明确规则重新定位；不能与普通返回混用重置逻辑。
- 原动作因编辑或停用等原因不再位于结果中时，回到邻近有效位置，不出现越界或空白。

## 4. 初始源码分析（修复前）

相关文件：

- [FitnessScreen.kt](../../../android_app/feature/fitness/src/main/kotlin/com/pockettoolbox/feature/fitness/presentation/FitnessScreen.kt)：页面状态、`detail()`、`back()`、列表状态选择和共享`LazyColumn`。
- [FitnessEditor.kt](../../../android_app/feature/fitness/src/main/kotlin/com/pockettoolbox/feature/fitness/presentation/FitnessEditor.kt)：`fitnessPicker()`与动作条目。
- [FitnessPagesTest.kt](../../../android_app/feature/fitness/src/test/kotlin/com/pockettoolbox/feature/fitness/presentation/FitnessPagesTest.kt)：现有页面交互测试，后续补充针对性回归场景。

已确认的静态事实：

1. 进入详情时保存`detailOrigin`，`back()`通过该字段返回；动作选择来源为`Picker`。
2. 已分别声明`pickerList`、`editorList`和`detailList`，但多个页面共用一个`LazyColumn`，随`page`替换列表状态和内容。
3. `detail()`设置`page = "Detail"`后立即启动协程执行`detailList.scrollToItem(0)`，操作发起时目标列表是否已完成切换需要验证。
4. 选择器的筛选与加载数量已有外层状态，动作条目已有`pick-${exercise.id}`稳定标识，可以继续复用。
5. 当前未见专门验证“动作选择列表滚动 → 详情 → 返回原位置”的页面测试。

待确认根因：共享列表容器切换内容与状态时的位置恢复，以及详情回顶部操作的执行时机。以上是排查方向，不能仅凭静态代码认定为唯一根因或Compose框架缺陷。

## 5. 建议修复范围与顺序

1. 先运行复现并补充回归用例，记录离开前和返回后的首个可见动作、索引与偏移。
2. 在`FitnessScreen.kt`中明确不同页面列表的身份，可评估使用`key(page)`隔离列表容器；各页面已有的列表状态继续保留在外层，不能随页面销毁。
3. 将“用户主动打开详情时回顶部”改为目标列表就绪后执行的一次性操作；普通返回和状态恢复不触发来源列表重置。
4. 优先复用现有状态。若验证后仍有位置丢失，再补充按当前选择上下文记录和恢复滚动位置，必要时以动作ID作为定位锚点，并处理结果集变化。
5. 在`FitnessPagesTest.kt`补齐返回路径测试。预计修改集中在页面层与测试，不涉及计划数据结构或数据库迁移；实际方案以复现结果为准。

## 7. 修复记录（2026-11-05）

- 对照实验：在`92d221b`的原版`FitnessScreen.kt`运行新增测试，返回后原动作不再可见，测试失败；恢复修复版后同测试通过。
- 按`key(page)`隔离列表容器，列表状态仍保留在页面外层；来源详情单独使用列表状态。仅主动打开新详情时执行一次回顶部，状态恢复不重置。
- 使用可保存的筛选上下文区分“结果集改变”和“详情返回”；切换日期、部位、搜索或筛选时回到新结果顶部，正常往返保留位置。列表条目变化继续使用Compose稳定键及索引边界处理。
- `FitnessPagesTest`覆盖加载更多后的工具栏返回、系统返回分发器、加入动作后返回、动作库返回、编辑清单返回、详情状态恢复；断言原动作屏幕偏移误差不超过1像素。
- 修改在本地工作区，未创建提交或发布。具体命令、结果与设备验证边界见[实施与验证](实施与验证-20261105.md)。
