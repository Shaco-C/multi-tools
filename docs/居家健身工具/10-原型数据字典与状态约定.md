# 居家健身工具 · 原型数据字典与状态约定

日期：2026-10-23。用于W01和原型实现，不是最终Room表结构。功能细节见09；所有样本均为内容草稿，不宣称教学审校通过。

## 1. 字典

| 字段 | 值/规则 |
| --- | --- |
| purpose | strength力量/稳定性、cardio有氧/体能、warmup热身/活动、stretch拉伸 |
| primaryPart | chest、back、shoulder、biceps、triceps、forearm、core、glutes、legs、calves、full；非力量可为空 |
| muscleParts | 教学主要/辅助部位的多选标签；与唯一统计主归属分开 |
| unit | reps次、seconds秒；禁止相互累加 |
| side | total整体、each每侧；每侧目标需左右均完成一轮才确认一组 |
| plan.status | draft草稿、active生效、archived归档 |
| day.kind | training训练、rest休息、unplanned未安排 |
| item.status | active有效安排、stopped结束剩余安排；停止不删除已确认事实 |
| event.status | valid有效、revoked撤销；撤销事件不进入统计 |
| timeSource | realtime实时确认、user用户补充、dateOnly仅日期补记 |
| contentStatus | draft待审样稿、reviewed已审核；本阶段不自动给reviewed |

每种器械采用稳定键：floor地面、dumbbellPair双哑铃、dumbbellSingle单哑铃、longBand长弹力带、loopBand短弹力圈、bench训练凳、anchorHigh高位固定点等。必需器械组内部全部满足；允许多组时组间任一满足。单哑铃不能匹配双哑铃动作，双哑铃可满足单哑铃条件；普通椅子不默认等于训练凳。

## 2. 概念对象

| 对象 | 必需字段 | 重要约束 |
| --- | --- | --- |
| Exercise | id/name/aliases/purpose/allowedPurposes/primaryPart/muscleParts/unit/side/equipment/intro/steps/cues/contentRevision/status | 复用03候选ID，不按名称或图片推断身份 |
| Plan | id/name/start/end/status/days | 范围为YYYY-MM-DD，自然日字符串，不作为UTC时刻归类 |
| PlanDay | date/kind/parts/items | 日期部位按力量主归属校验，非力量不强填肌肉 |
| PlanItem | id/exerciseId/name/primaryPart/purpose/unit/side/targetSets/targetValue/status | 固定安排快照；同计划日同动作ID只一条，移除重加恢复原条目 |
| SetEvent | id/requestId/planId/day/itemId/exerciseId/ordinal/status/recordedAt/timeSource/actualAt/snapshot/actual | id与requestId稳定；ordinal只是组序位 |
| ActualValue | total或left/right | 非负语义不混淆：原型只接受正整数或null，null表示未填写，不填0 |
| Preferences | equipment/theme/recoveryEnabled | 偏好修改不删除旧安排；主题与提醒不改变统计 |
| AppState | schemaVersion/demoToday/plans/events/customExercises/preferences | 一次写入一份状态，保存失败不先更新画面 |

实际时刻可空；记录操作时刻始终存在。事件快照至少有名称、内容版本、主归属、主要/辅助参与、用途、单位、左右口径和当时目标。

## 3. 变更与不变量

1. 记组前校验计划生效、计划日非未来、条目可执行、目标未达；补记过去日期先明确训练日期与时间来源。
2. 相同requestId返回既有结果；同一条目ordinal只允许一个有效事件。撤销重记生成新事件，旧事件保持撤销。
3. 同一planId/day/exerciseId删除后再加入恢复原itemId；即使有效组数为0，有撤销历史也仍是有历史。
4. 已有任何事件后，条目purpose/unit/side/primaryPart不直接切换；名称/目标等编辑遵守04快照规则。
5. 当前安排的目标组数不小于有效已完成组数。停止后的历史另列，不参与当前未完成目标。
6. 草稿不进入时间轴安排和统计；归档不出新任务，历史有效事件仍统计。恢复导入替换整个健身原型状态，不叠加缓存。
7. 原型用浏览器本地存储模拟离线数据。失败在持久化边界前返回，不把内存已变更当作成功；正式Room事务另验。

## 4. 统计公式

先按训练日期（含首尾）、计划范围、有效状态筛事件，再按所需用途筛选：

- 总训练天数：strength/cardio事件的不同day数量。
- 连续值：若今天有训练从今天向前，否则从昨天向前；中间空日终止。仅热身/拉伸不算。
- 部位组数：strength按快照primaryPart计事件数；每事件只加一次。
- 部位天次：strength按primaryPart分组后对day去重；跨部位可重叠，不能相加当总天数。
- 动作组数/段数：按exerciseId计有效事件；动作天次对day去重。
- 实际值：同动作、同单位和side口径内加已填值；普通显示已填组/有效组，每侧分别显示左右覆盖。
- 顶部全部用途概览只受日期＋计划过滤；下方用途、主部位/动作和指标不会偷偷改变顶部口径。
- 分类和内容更新不重写事件快照；不同稳定动作ID即使同名也不合并。

| D11 | 过去补记未填实际时刻 | timeSource=dateOnly，恢复仅按日期描述 |
| D12 | 模拟保存失败/导入损坏备份 | 原state及已显示进度保持，错误可见，可重试 |

## 6. 原型限制必须可见

浏览器JSON导出只演示结构化资料和原型自建图片，不是已完成的Android ZIP媒体备份。原生文件原子切换、进程被杀后的恢复、动画解码内存及真实APK大小留待工程验证。图像解剖、步骤与许可审核另有台账，不由数据结构测试自动通过。
