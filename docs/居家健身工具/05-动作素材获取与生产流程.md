## 1. 建议采用的组合

将候选动作变成可发布内容，建议分三条线并行处理：

1. **文字与动作身份**：先从 free-exercise-db、wger 等来源匹配候选动作，提取英文名、器械、肌群和教学底稿，再编辑为统一中文结构。机器匹配只产生候选对应关系。
2. **肌肉图**：采用许可明确的人体正背面底图，制作一次经过审核的肌群区域库；分类图、动作主次肌群图从同一套区域生成。这一部分已有可核验的 CC BY-SA 3.0 原图候选，详见第 4 节。
3. **姿势与步骤图**：优先选择许可、动作变式和画面均合格的现有素材；缺失时按已审核脚本原创制作。先用 12 个动作验证来源组合，再决定是否扩大采用 RepDB 的统一静态图，或购买 ExerciseDB.io 动图。

首版每个发布动作都有可离线使用的中文介绍、肌肉图和静态教学。动图单独审查、按通过情况增加；不会因某个来源没有 GIF 而让用户看不到教学。

这里的“获取”发生在内容制作阶段。最终应用读取审核后随安装包内置的资源，训练时不访问第三方接口。来源清单及数量变化不直接推送到用户的动作库。

扩充后的候选数以 03 的实际去重清单为准。内容记录另行维护三组字段：**用途**（力量/有氧/热身/拉伸等）、**统计主部位**（每条只归一个主分类，避免汇总重复）和**主要/辅助肌群**（允许多个，用于筛选与人体高亮）。统计归属不表示动作只作用于该部位；源库的 `category` 也不能未经映射直接充当本项目的用途或统计主部位。

## 2. 具体从哪里取、取哪些内容

### 2.1 free-exercise-db：适合建立候选映射和说明底稿

已核实的入口：

- [官方 README：数据组织与本地使用方式](https://github.com/yuhonas/free-exercise-db)。
- [字段 Schema](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/schema.json)。
- 单条记录：[Dumbbell_Flyes.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/exercises/Dumbbell_Flyes.json)、[Pushups.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/exercises/Pushups.json)、[Plank.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/exercises/Plank.json)。

该库把单条动作放在 `exercises/<来源动作ID>.json`；`images` 中是相对 `exercises/` 的图片路径。采用时以记录中的实际值为准，不根据中文名猜路径。固定来源提交版本后再保存对应文件，不能长期指向会变化的 `main`。

| 获取字段 | 本项目的处理 |
| --- | --- |
| `id`、`name` | 保留来源 ID，映射本项目稳定 ID；英文名作为检索别名 |
| `primaryMuscles`、`secondaryMuscles` | 作为肌群映射候选，经过审核后进入本项目肌肉字典 |
| `equipment` | 初始器械标签；结合步骤补全训练凳、固定点等必需条件 |
| `instructions` | 中文底稿来源；重新组织为准备、过程、还原和关键提示 |
| `force`、`mechanic`、`level`、`category` | 保存来源值，按本项目规则映射；空值保持未知 |
| `images` | 逐项检查文件存在、数量、尺寸、画面、来源许可及对应动作变式 |

本次查看的三个单条 JSON 均列出两张 JPG；Schema 并未保证每个动作恰好两张，也没有独立的教学 GIF 字段。两张图片路径不证明它们已经覆盖正确的起止姿势。

实际发现的补全需求：`Dumbbell_Flyes` 的 `equipment` 只有哑铃，步骤却要求平板训练凳；`Plank` 的辅助肌群为空，不能因此断言没有任何辅助参与。源库的 `chest`、`shoulders` 等粗分类也不能自动推导成胸肌细分区域或三角肌某一束。

图片使用仍受 [根许可证](https://github.com/yuhonas/free-exercise-db/blob/main/LICENSE.md) 与具体素材来源核验结果约束。本次没有取得所有照片的逐图作者及权利链。文本条目匹配成功与照片可以正式分发是两项独立状态。

### 2.2 wger：按动作、译文和媒体分别取来源信息

官方 [API 文档](https://wger.readthedocs.io/en/latest/api/api.html) 提供 API 索引和 Schema 入口。当前 [路由源码](https://raw.githubusercontent.com/wger-project/wger/master/wger/urls.py) 注册了下列读取资源：

| API 路径 | 用途 |
| --- | --- |
| `/api/v2/exerciseinfo/` | 读取组合动作信息，作为样本采集的优先入口 |
| `/api/v2/exercise/`、`/api/v2/exercise-translation/` | 分开处理动作身份与语言内容 |
| `/api/v2/exerciseimage/`、`/api/v2/video/` | 获取图片、视频及各自元数据 |
| `/api/v2/muscle/`、`/api/v2/equipment/`、`/api/v2/exercisecategory/` | 获取字典；不硬编码未知的数字 ID |
| `/api/v2/language/`、`/api/v2/license/` | 解析语言和许可字段 |
| `/api/v2/deletion-log/` | 供后续内容更新检查删除或替换事件 |

**核验边界**：上述路径由官方路由源码确认；本次网页工具未成功取得 `wger.de` API 的实时 JSON 响应。因此不能宣称接口连通性、生产部署版本、筛选参数或当前有效数量已实测。试采样时先读实际部署的 Schema，再按分页取得需要的记录，不能套用未知参数直接抓取。

2026-10-23补充实测：内容小样流程成功读取 `/api/v2/muscle/?limit=100`，返回15个肌群，已保存 `content/fitness/pilot/muscles/dictionary.json`。这只更新肌群字典的连通性结论，不代表上表全部动作/媒体接口已实测；SVG来源提交与校验见同目录provenance。

官方 [序列化字段定义](https://raw.githubusercontent.com/wger-project/wger/master/wger/exercises/api/serializers.py) 可核对动作的 `id/uuid`、主次肌群与器械，译文的名称、说明、别名，以及媒体的独立许可、作者、原始链接和改作来源。图片有 `is_main`，但它表示主图，不表示动作第一步；视频还提供尺寸、时长等信息。肌肉字典有名称、正背面标记及主次肌群图 URL。

处理时保留译文与每份媒体自己的署名，不能只给整个动作写一个“wger”。API 中已有中文也须人工审校；多语言支持不等于每条都有合格中文。HTML 说明转成应用自己的结构化段落，不直接执行或展示来源网页脚本。

官方模型当前将 [静态图片](https://raw.githubusercontent.com/wger-project/wger/master/wger/exercises/models/image.py) 与 [视频](https://raw.githubusercontent.com/wger-project/wger/master/wger/exercises/models/video.py) 分开管理。一个动作可能没有图、只有主图或只有视频，必须按实际样本建立缺口表。动作与媒体使用各自的内容许可；应用代码的 AGPL 不可用来推定所有媒体适用同一许可。

### 2.3 RepDB：作为统一静态图候选，先确认分发安排

实际数据文件为仓库根目录 [exercises.json](https://github.com/RepDB/exercise-dataset/blob/main/exercises.json)。根据 [官方 README](https://github.com/RepDB/exercise-dataset)，其中有 `schema_version`、`count` 与 `exercises`；条目包含稳定 ID、多语言名称与步骤、主次肌群、器械、单侧属性，以及图片路径。图片形态为 `images.flat.start/peak` 或单张 `images.flat.main`，不能固定按两张图读取。当前公开图为 512px WebP，语言为英语、德语和西班牙语。

试采样时按目录 ID 匹配选中的动作，再按记录给出的路径取少量图；不从相似名字自行拼出图片地址。主次肌群和单侧属性只作为待审核输入；现有条目可能共用同一图片，动作身份不能以图片文件名去重。

[数据及图片许可](https://raw.githubusercontent.com/RepDB/exercise-dataset/main/LICENSE-DATA.md) 允许署名后的应用内使用，但禁止作为数据集再分发，禁止将图片用于生成式 AI 参考、改风格或训练；付费预览动画也不属于免费可发布内容。用于应用内展示的许可不能直接推导为可以把整套 JSON 和图片提交到公开仓库。采购或采用前明确原始资料保存位置、构建注入方法与署名页面，再进入批量制作。

### 2.4 ExerciseDB.io：需要动图时走明确的商业资料包路线

官方 [FAQ](https://exercisedb.io/faq) 说明资料包按动作 ID 配对 JSON 与 GIF，购买后可以自行托管或打包进应用；[使用条款](https://exercisedb.io/terms) 限制原始资料库及媒体独立再分发。生产文件来自正式购买交付包，本文不猜测受限下载 URL，也没有采购。

先用官方可评估样例确认画面、起止和循环，再核对目标动作实际覆盖、中文版改编、转码、截帧及公开仓库安排是否被具体许可允许。不得把其他同名 ExerciseDB 服务的 API、数据或媒体当作同一购买授权。付费也不替代教学审核。

## 3. 静态图、动图与文字各自如何生产

### 3.1 静态教学图

每个动作建立一份画面脚本：具体变式、器械、拍摄视角、准备姿势、运动末端、必要中间步骤、回到安全位置的说明。动态动作通常准备 2–4 帧，复杂动作按需要补帧；静态保持动作使用进入、保持要点和退出说明。

现有图片只有在动作变式、器械和角度准确匹配时才采用。保留原图；在允许的范围内输出统一背景或留白的显示版本，生成列表缩略图；裁切不能遮掉脚部支撑、手部握法或器械固定点。补帧优先同一来源、同一示范体；无法保持一致时整套重制，不能把不同动作照片拼成连续过程。

原创制作可采用经审核的真人拍摄、插画或 AI 辅助画图。使用 AI 时先有动作脚本，再逐帧核对肢体、支撑、握法和器械连接；生成输出进入待审区。没有经核验的解剖/动作审稿，就不能标为“标准教学已审核”。

### 3.2 动态教学

动图的候选顺序是：同一动作已有的许可明确视频/GIF → 已授权商业动作包 → 原创连续动作素材。需要转码、剪辑或截帧时先确认许可，再输出适合 Android 的格式并实测。

审核整个循环的运动路径和还原过程，不能只看首帧好看。动图可暂停，静态关键帧仍可单独查看；列表只显示封面。没有合格动图时使用已审核步骤图，不用静态帧交替闪动冒充连续动作，不从教学网站直接录屏后当作原创。

### 3.3 中文介绍与肌群映射

建立术语表，先区分“胸部飞鸟/反向飞鸟”“地板卧推/平板卧推”等变式，再翻译。机器或人工初稿都按“简介、器械准备、准备姿势、运动过程、还原、易错点、计量口径”重整，删除不适合本产品的模板化次数和时长建议。

复核分两遍：中文编辑检查名称、别名、单位、可读性；具备相应知识的内容审核人员检查姿势、器械、肌群与图文一致性。对同一动作来源冲突时留下待解决项，不能简单取多数或让模型补造结论。源库只有部位级信息时，先保持该粒度，获得依据后再细分肌肉。

## 4. 肌肉图：已有原图来源，区域映射仍需制作

### 4.1 本次新核实的来源链

wger 的 [肌肉图目录](https://github.com/wger-project/wger/tree/master/wger/core/static/images/muscles) 包含正背面 SVG、`main` 和 `secondary` 图层目录。其 [SOURCES](https://raw.githubusercontent.com/wger-project/wger/master/wger/core/static/images/muscles/SOURCES) 明确指向以下原始文件页：

| 原图 | 文件页核实结果 |
| --- | --- |
| [Muscular system.svg](https://commons.wikimedia.org/wiki/File:Muscular_system.svg) | 文件页作者为 Termininja，标注 CC BY-SA 3.0，提供原始 SVG |
| [Muscular system-back.svg](https://commons.wikimedia.org/wiki/File:Muscular_system-back.svg) | 文件页作者为 Termininja，标注 CC BY-SA 3.0，提供原始 SVG |

两份原始文件可作为**许可依据已找到的底图候选**；按相应许可保存署名、原始链接、修改说明，并以相同或许可兼容方式分发改作。具体采用文件版本和原图来源信息也进入台账。[CC BY-SA 3.0 官方说明](https://creativecommons.org/licenses/by-sa/3.0/)

这比“网上找一张人体图”具体，但尚不等于现成产品图。当前未逐一核验 wger 每个高亮 SVG 的改作历史、图层与本项目肌群的对应关系，也未完成原图的解剖准确性和手机可读性审核。不能直接宣称 `main/secondary` 中的数字编号已经覆盖本项目全部分类。

### 4.2 实际生产步骤

1. 从已确认的原始文件页选择版本，保存文件、许可页面证据及文件校验值；若采用 wger 改作版本，另记录 wger 版本与相关改动来源。
2. 视觉制作人员整理正背面母版、轮廓和区域；去除不适合小屏的标签时保留修改说明。原图不适合产品画风时，可以另行原创统一底图，但仍须解剖审校。
3. 内容审核人员确认本项目肌肉字典与区域映射，例如“大部位—具体肌肉—正背面区域”；未覆盖的深层肌肉用文字说明或补充局部图，不靠颜色猜位置。
4. 对每个动作输出 `主要参与区域 + 辅助参与区域 + 文字标签`；主次由审核后的动作记录决定，不能由图层颜色反推训练效果。
5. 分类图使用该分类的区域集合；列表图可使用适合小尺寸的概括视图；详情允许查看正背面。三者来自同一份映射，避免分类说练胸、动作图却高亮肩。
6. 在三套应用主题和小屏大字体下检查；颜色之外提供图例/标签。通过后锁定底图和映射版本，再按动作批量输出。

此方案无需为每个动作单独生成一具新人体。动作增多时主要新增映射和姿势素材，底图能持续复用。

## 5. 未来试采样：12 个动作的验收矩阵

下面是下一阶段要制作和验收的样本，不是已到手的 12 个完整素材包。“JSON 已核对”只表示本次读过该条目元数据；其图片未下载、未视觉审核、未逐图完成许可核验。

| 动作 | 初始取材路线 | 该样本重点验证 | 最低产物与缺失回退 |
| --- | --- | --- | --- |
| 标准俯卧撑 | free-exercise-db `Pushups` JSON 已核对；同时比对 wger 候选 | 徒手复合动作、胸/肩/三头层级、起止姿势 | 合格起止图＋主次图；照片来源不合格则整组原创 |
| 哑铃地板卧推 | 按英文名与“地板”支撑条件检索 wger/RepDB | 不能拿训练凳卧推替代地板版本 | 地面接触清楚的起止图；未匹配到则原创 |
| 平板哑铃飞鸟 | free-exercise-db `Dumbbell_Flyes` JSON 已核对 | 哑铃之外必须补训练凳；不能错配反向飞鸟 | 起止＋还原提示；补中间帧需同一示范体 |
| 单臂哑铃划船 | wger/RepDB 精确匹配所选支撑变式 | 单侧、支撑手与腿、每侧次数 | 与候选定义一致的步骤图；凳支撑版不能替代无凳版 |
| 哑铃侧平举 | wger/RepDB 静态图候选 | 肩部细分、器械握法、正背面对应 | 两端图＋必要中间帧；难以辨认时整组重制 |
| 哑铃弯举 | wger/RepDB，锁定同时双臂或交替版本 | 手腕方向、肩肘位置、次数口径 | 一套明确变式图；交替与同时版本分别映射 |
| 弹力带三头下压 | wger/RepDB，优先明确固定点的素材 | 固定高度、器械连接、不能用绳索器械图冒充 | 固定点可辨认的全套步骤；缺图优先原创 |
| 徒手深蹲 | wger/RepDB 徒手版本 | 全身视角、脚部支撑、腿/臀分类映射 | 起止图＋动作提示；不截去脚和膝部 |
| 哑铃罗马尼亚硬拉 | wger/RepDB 精确变式匹配 | 与普通硬拉区分、躯干与器械路径 | 关键姿势图；额外选择其一验证连续动图 |
| 臀桥 | wger/RepDB，锁定双腿徒手版本 | 地面支撑、臀部图层、保持与重复区别 | 起止图；不混入凳上臀推或单腿版本 |
| 前臂平板支撑 | free-exercise-db `Plank` JSON 已核对；专业内容复核 | 秒数、静态保持、核心标签不能只信空辅助数组 | 进入/保持/退出说明与关键图；不制造往返循环 |
| 站姿提踵 | wger/RepDB，锁定平地徒手版本 | 小腿区域、平地与台阶、双脚与单脚差异 | 起止图；台阶版本须另列器械条件 |

每个样本都要验收：本项目与来源 ID 对应正确；中文字数适合详情阅读；肌群区域可解释；列表双图能辨认；静态图顺序明确；许可及署名完整；无网络时可展示。动图增强另验收暂停、循环、帧率/解码与静态回退。

第一轮产出一份“12 行 × 文字/肌肉图/姿势图/步骤图/动图/授权/审核”的状态表。用真实的缺口率和制作耗时决定后续来源比例，不拿源库总条数直接当本项目覆盖率。

## 6. 不完整素材如何处理

| 缺口 | 处理规则 |
| --- | --- |
| 名字近似但器械或支撑不同 | 保留为待匹配，不直接关联；确认变式后再使用 |
| 只有英文说明 | 可进入中文初稿队列，审校通过前不发布 |
| 缺辅助肌群或只有粗部位 | 保留未知/粗粒度，补依据后细分，不自动补出“精确发力” |
| 只有一张姿势图，动态过程无法理解 | 同来源补图或原创整组；仍不足则暂缓该条目 |
| 缺 GIF/视频 | 使用完整步骤图，正式页面不显示空播放器 |

内置动作缺必备内容时留在候选库，不能借用个人自建动作允许“暂无图片”的规则来凑内置发布数量。

## 7. 资料台账与存放位置

一个动作可以对应多个来源，一张图片也可以有多个处理版本。动作记录和媒体台账分开，统一关联本项目稳定 ID。

| 台账 | 必备信息 |
| --- | --- |
| 动作对应表 | 本项目 ID、来源与来源 ID、具体变式、用途、单一统计主部位、匹配依据、来源版本、审核状态 |
| 中文内容 | 原文出处、语言、原稿版本、中文稿、编辑者、审稿者、日期、未解决问题 |
| 肌群映射 | 动作 ID、主要/辅助区域、文字依据、底图版本、映射版本、审核人 |
| 原始媒体 | 资源 ID、动作 ID、作者、原页面与文件 URL、取得日期、许可与证据、本地文件、校验值 |
| 显示版本 | 原资源 ID、裁切/压缩/改色/转码说明、顺序与封面用途、尺寸、体积、内容版本 |
| 分发规则 | 应用包是否允许、公开仓库是否允许、可否改作/截帧/生成参考、署名文本、限制与待核对项 |

建议沿用 02 中约定的位置：可公开的清单、台账与原创母版进入 `content/fitness`；审核后的 Android 资源进入 `android_app/feature/fitness/src/main/assets/fitness` 下的 `catalog`、`media`、`attributions`。这些是实施阶段建议，本文没有创建资源目录。

受限的第三方原包放在受控内容存储，公开仓库仅保留不受限制的映射和构建说明。许可证允许 APK 内展示，不意味着允许用户备份中导出整套第三方媒体；内置内容通常按 ID/版本引用，用户自己的图片按本工具备份规则处理。是否能公开某份改作数据，要逐来源判断，不能默认删掉原作者就成为原创。

## 8. 版本更新与增量处理

1. 来源采集固定提交/数据版本、抓取时间与文件校验值。生产包有独立内容版本；不由运行时远程 URL 决定内容。
2. 后续只对新增、变更、删除的来源条目生成差异清单；同一来源 ID 未变化不代表图片内容未变，文件校验值也要比较。
3. 新增条目从候选开始；文字变更重审文字；图像、器械、计量或主次肌群变化需重审相关画面与映射。
4. 上游删项或改许可时进入人工处理，不自动删除用户计划；核对已取得版本的使用证据和变化原因，再决定继续分发、替换或下架。
5. 本项目动作 ID 保持稳定，来源 ID 仅为外部映射。名称和图片变化不能让历史训练指向另一个动作。内容改版与用户记录迁移按 04 的历史保护规则执行。
6. 内容包发布前检查资源清单与实际文件一致、引用无断裂、署名可离线查看，并保留上一通过版本便于回退。首版可随应用更新交付，不为此次需求引入运行时内容下载系统。

## 9. 谁负责、哪些环节不能自动放行

| 角色职责 | 可借助自动化 | 必须人工确认的出口 |
| --- | --- | --- |
| 产品负责人 | 覆盖矩阵、缺口汇总、候选去重提示 | 收录范围、动作变式边界、发布覆盖缺口 |
| 内容编辑 | 拉取公开元数据、术语匹配、翻译初稿 | 中文名称、说明、单位、左右计量、器械条件 |
| 动作内容审核 | 标记差异、并排查看图文 | 动作路径、支撑握法、图文一致、肌群映射；应由具备相应知识的人负责 |
| 视觉制作 | 已审核区域批量输出、压缩、生成缩略图 | 底图正确性、关键帧可读性、跨帧一致性 |
| 素材与许可负责人 | 整理许可字段与署名清单 | 作者与来源证据、具体分发方式、改作限制、采购许可 |
| 开发与验证 | 清单校验、文件哈希、尺寸和体积检查 | 真机离线展示、内存/滚动、主题与无障碍、安装包体验 |

角色可以由同一成员兼任，但每一项审核都要有明确责任人和记录。自动化只能将条目标记为“待审”或给出技术检查结果；不能把翻译成功、图片生成成功或文件存在当作教学与授权通过。
