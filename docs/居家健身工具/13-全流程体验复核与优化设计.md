# 居家健身工具 · 全流程体验复核与优化设计

日期：2026-10-24。复核基线：01、09—12以及当前本地原型。

**本文保留优化前的体验分析与设计提案，以下问题、证据及“尚未实施”表述均对应当时基线。用户随后确认实施，当前18项原型改进及验证状态以[14-体验优化执行与验收记录](14-体验优化执行与验收记录.md)为准。** 12中已经完成的动作选择改进作为基线保留。新建议按“用户当前任务能否顺利完成”排序。

## 1. 结论与证据范围

最值得继续优化的方向是：打开后找到今天该做的事；从不同入口操作时保留原来的意图与资料；完成一次训练后能够方便地检查和修正记录。

本轮阅读了当前页面、事件处理、计划选择规则及既有设计，并在独立`localhost:5183`资料中走查部分分支，未替换用户`127.0.0.1:5183`中的计划和草稿。

## 3. 各流程的具体设计

### UX01：打开之后，主按钮回答“我现在能做什么”

现状见E01、E04。继续入口目前按页面第一个动作定位，没有选择日期、是否已完成、是否存在动作的判断。

建议采用下表，不动用户已确认的时间轴和两张首页卡片：

| 当前状态 | 主操作 | 点击后的行为 |
| --- | --- | --- |
| 正在浏览过去/未来日期 | 回到今日训练 | 回到今天，展示今天的任务；历史补记仍在历史日期的动作区 |
| 今天有剩余动作 | 继续：深蹲1/4组 | 定位上次停留且仍有效、未完成的动作；该动作已完成则定位下一个剩余动作 |
| 今天的安排组数已经记满 | 查看今日记录 | 展示当天实际记录，允许撤销误记和补实际值 |
| 今天明确休息 | 查看日程 | 保留休息安排，临时安排作为次要入口 |
| 今天未安排且无记录 | 安排今天 | 进入单日快捷路径 |
| 当前无剩余安排但有历史 | 查看今日记录 | 明确“当前无剩余安排”，不显示全部目标达成 |

有多个计划时，在继续入口同时展示所属计划；日期切换不自动记组。卡片仍区分今天与正在查看的日期，所选日动作区增加醒目的完整日期和“历史补记/未来预览”状态。

验收：选昨天后点主操作不会继续定位昨天；第一项已完成时能定位剩余项；空白日主操作可执行；从教学返回仍落在原动作。

### UX02：新建与编辑的草稿保护必须统一

E02已经复现：顶层新建有保护，安排单日绕过保护。不同计划的“编辑”也直接进入`startEditor`，应一并纳入。

建议所有入口先识别“当前草稿属于哪个计划、哪次新建、哪个日期”：

- 命中同一份草稿：直接继续，定位到上次步骤/日期。
- 进入另一份任务而已有草稿：展示草稿名称、日期和最后暂存时间，主操作为“继续原草稿”。
- 当前单草稿版本中，次操作明确叫“新建并替换草稿”或“替换为本次编辑”，展示影响后再确认；不能将其叫“另建一份”而实际覆盖。
- 支持多草稿属于后续数据能力；实现前不承诺自动保留两份。
- 草稿保存失败时保持当前输入，并给出重试入口；恢复成功后才显示已暂存。

验收：新建、安排当天、从动作创建、编辑其他计划四个入口都无法静默覆盖已有草稿；退出暂存不改变执行中的安排。

### UX03：把“下一步报错”改成“我知道该去哪里补齐”

结构性错误（日期无效、范围无法建立）仍在相关字段旁阻止继续。动作/组次缺项建议允许进入**预览检查页**，集中展示，不允许保存为生效计划。

```text
计划检查 · 还有2处待补

10月24日  肩部未选择动作                [去选择]
10月25日  深蹲每组次数未填写            [去填写]

10月26日  未安排                       允许保留

[暂存退出]                    [保存计划：待补齐]
```

- 点击去填写，定位对应日期、部位和动作，聚焦首个错误字段；修正后回到检查页。
- 不能用“未安排”提示淹没真正的错误；休息/未安排均允许保留。
- 预览突出每一天的部位、动作和目标，长范围按周/日期折叠。
- 保存成功默认进入计划详情并提供“去今天训练”；未来计划显示下一训练日期。

这是对现有“预览前整体校验”的调整建议，不是放宽生效计划的完整性要求。下一轮实现后需更新对应浏览器验收预期。

### UX04：备份必须形成用户能够恢复的闭环

先处理E10的容量边界：导出与导入共用版本、总量、媒体及引用校验。产品验收要求是：**在支持范围内创建的资料，标准备份能够由本工具恢复。** 具体容量和打包方式由后续媒体方案实测确定，不能仅提高一个数字并宣称解决。

- 导出前展示计划数、记录数、个人图片数、估算大小和备份范围；对当前恢复能力不支持的资料明确说明，并保留原始资料导出路径。
- 原型浏览器仅发起下载时，提示“已发起下载，请确认文件已保存”；正式端完成写入校验后再标记备份成功。
- 恢复预检展示“当前资料→备份资料”的数量、日期范围、图片完整性及替换影响。
- 恢复失败继续使用原资料；媒体缺失、空间不足或版本不支持时，提示对应的处理入口。
- 首版保持替换恢复语义；合并恢复和自动回退快照需要单独设计与工程验证。

六张图的容量问题目前是静态推导；正式ZIP媒体恢复仍属于11中的既有缺口。本轮不会将无图JSON恢复通过解释为带图备份已经可靠。

### UX05：首次使用和“今天随便练几组”应有较短路径

首次进入正式工具，主操作“安排今天”，次操作“先看动作库”；器械选择可用简短面板收集，允许稍后调整。已有用户直接回到今日训练，不重复展示引导。

建议单日快捷路径：

```mermaid
flowchart LR
    A[安排今天/这一天] --> B[选择部位或活动]
    B --> C[独立选择动作]
    C --> D[填写目标并检查]
    D --> E[保存单日计划并进入训练]
```

日期由入口明确预填为同一天；名称按日期生成，可展开修改。“安排10月24日”不能默认生成24—25日。完整日期范围创建继续保留，不新建一套游离于计划和统计之外的记录模型。

### UX06：多日安排先看总览，再批量配置

- 第二步提供“日期＋部位＋状态”的周/月概览，选中日再编辑；长范围不依赖一整条日期按钮。
- 批量应用先选目标日期，再选部位/休息状态；默认仅应用到未安排且无历史的日期。
- 目标日有配置时展示将受影响的安排；含完成或撤销历史的日期保持原有保护。
- “复制这一天”可扩展多选目标日，明确只复制动作和目标，记录从0开始。
- 保存预览显示训练日、休息日、未安排日及待补日数量，支持直达具体日期。

这是补齐F07原有批量能力的体验设计，不将已经完成的单日选择改进当成多日批量也已完成。重复周模板放到UX18。

### UX07：从动作详情发起的任务应带着动作继续

E03中的动作意图需要保存为待加入项，包含动作ID、来源和用户明确选择的日期。

- 无计划：显示“准备加入：标准俯卧撑”，进入建计划后在选定日期的草稿中保留该动作，补齐主部位和目标后检查保存；用户可明确移除。
- 有计划：先选计划，再在其有效范围选择日期；保留已有日期意图，变更导致日期无效时提示重新选择。
- 当天已经安排同一动作：提供“查看/调整现有安排”，不让用户再次输入后悄悄忽略新目标。
- 曾停止的同一动作：说明恢复原条目、目标和进度；不复制成从0开始的第二份。
- 取消创建时不产生生效计划或完成记录。

验收：从详情加入不需要再从全库寻找一遍；起止范围外日期不能等到最终提交才报错。

### UX08：区分“主练这里”和“这个部位也参与”

E05说明当前肩部浏览页的辅助参与范围较广，容易与计划选择中的肩部主动作产生认知差异。

建议分类默认显示主要训练归属，提供“也看辅助参与”的显式选项；分类数量按同一模式计算。列表在必要时标注“主练胸部，肩部辅助参与”。这是自由库默认浏览方式的调整提案，统计仍沿用单一主归属。

不知道动作归属时，允许从动作库顶栏搜索图标进入**独立全库搜索页**。分类首页继续只展示分类，不恢复分类下方的全量列表。分类内无结果时提供“在全库搜索此名称”，返回后保留原分类与搜索。

### UX09：选择器的无结果状态要能继续完成任务

新选择器已具备搜索、分批、查看已选和返回保留，这些能力继续沿用；补齐两个边界：

1. “重置筛选”恢复当前分类和我的器械默认，清除临时搜索/器械标签/来源条件；“查看全部器械”作为另一个明确入口，避免重置悄悄扩大器械范围。
2. 无匹配时提供“新建我的动作”。从选择页进入时预填当前用途与主部位，按钮明确为“保存并加入10月24日”；保存后底栏计数更新，目标回清单填写。

如果新动作被当前来源或搜索条件隐藏，明确提示已经加入，并提供查看已选；不通过修改用户的器械偏好来让结果勉强出现。所有必要器械继续完整匹配。

### UX10：训练时把当前动作和组数放在操作中心

首页保留时间轴、两张概览卡和简短恢复参考；进入继续训练后定位/突出当前动作，其他动作折叠为简洁清单。先用既有条目ID和进度实现展示聚焦，不必引入一套新的训练开始/结束记录。

```text
10月24日 · 下班训练
徒手深蹲                  已记录 2 / 4组
本组目标20次

[图片 / 查看教学]
[完成第3组]

刚才记录：第2组            [撤销这一组]
其他动作：俯卧撑…          [查看清单]
```

- 每次确认只做一组记录，不弹实际次数输入；按需要再补实际值。
- 完成目标后展示“该动作组数已记完”和“下一个动作”；由用户点击进入，不在休息时突然切走。
- 查看教学保留固定返回训练入口、动作名称和原组数，返回仍停在原卡片。
- 撤销明确动作和组号；保存失败保持原计数，可重试。全部组数记满的提示不冒充已填写实际次数。
- 休息计时属于可选增强，单独开启、能停止；不作为记组的必经步骤。

### UX11：补记一次训练，减少逐组重复确认

建议新增“补记这个动作的多组记录”：选过去日期、动作、补记组数，一次预览确认后生成各组记录，数量上限受剩余目标约束。默认只确认组数，实际次数仍可选填。

- 缺少具体时刻时保留仅日期补记；不把补记发生的现在写成实际训练时间。
- 训练卡区分“训练日期/时刻”和“补记操作时间”，E11中的“最近”改为明确文案。
- 支持“撤销本次补记N组”，涉及的事件关联、重复请求和整批失败回退需工程设计；单组明细仍可查看。
- 跨计划同名动作的记录显示日期和所属计划，改实际值前能确认对象。
- 今天记组、历史补记和未来预览使用稳定且不同的按钮文案；未来不能直接记组。

### UX12：看哪一天，就能编辑哪一天；归档仍有参考价值

- 计划卡主操作按状态显示继续今天、查看下一训练日或回看记录；日期已结束不自动等同归档。
- 计划详情的“编辑10月24日安排”保留所选日期，定位动作步骤；修改整体范围由“编辑计划信息”单独进入。
- 归档详情分别展示原安排与实际记录。没有实际记录时显示“当日未记录训练”，仍可看到原动作和目标。
- 归档的复制入口明确为“用这一天创建新安排”，选择生效计划和目标日，生成新条目，不复制记录；目标日保护规则保持。
- 归档保留历史作为常用次操作；彻底删除收进更多菜单，并展示将删除的计划与记录数量。

### UX13：统计先回答问题，再展开条件与解释

首屏围绕“这段时间练了几天、主要练哪些部位、记了多少组”组织；近7/30天和自定义继续保留。日期/计划为全局条件；榜单用途筛选放进明确标注的“下方训练明细”区域，概览仍明确为全部用途，避免同一筛选看起来只改一半页面。

- 部位与动作条形行、次数/时长行的主点击统一进入组成记录。教学作为单独的次入口，修复E09中的点击预期差异。
- 记录明细显示日期、计划、动作、实际值与补记状态；可跳转当天历史并返回原统计条件。
- “覆盖3/8组”改为可读说明“8组中有3组填写了实际次数”；每侧分别展示，不把未填当0。
- 切到纯有氧或活动明细时使用相应单位，不把段数写成力量组数。
- 不根据单一部位次数榜判定训练均衡、恢复完成或健康状况。

### UX14：恢复参考围绕当前任务展示

目前摘要只取最近一条力量记录，未必与今天准备练的部位有关。建议首页先显示今天计划部位的最近记录，最多两条，其余展开；计划编辑时再对所选部位和相邻训练日提示。

- 先给事实：“胸部上次记录在10月22日”，再提供一般参考和查看依据。
- 具体时刻未知时按日期描述；不生成精确小时倒计时或恢复百分比。
- 同一训练过程中不每组重复提醒；关闭提醒不影响记录和统计。
- 提示提供查看记录、修改安排或保留安排，不自动换日/换动作。

本节是已有F04的呈现与触发设计，不新增各肌群固定恢复时长的医学结论。

### UX15：自建动作先填够用的信息

必填区优先展示名称、用途、主要训练部位、器械及“按次数还是计时/是否每侧”；简介、别名、步骤、图片等折叠到补充信息。来自选择器时复用UX09的预填和返回规则。

- 图片可选，无图也能安排和记组；选择失败明确保留文字，不丢整张表单。
- 图像裁切和预览需要专门验证；当前单图原型不冒充已经支持多图编辑。
- 修改被计划引用的动作前，展示引用范围，说明修改对以后新增、现有安排及历史快照各自的影响。
- 停用动作只影响新的候选，既有安排仍能识别；恢复入口明确可找到。
- 主要训练部位用用户语言解释，统计归属规则放在需要了解时展开；不要求用户先理解数据字典。

### UX16：保存、返回与危险操作遵循同一套反馈

已经自动暂存成功的计划，返回时直接保留，不重复弹确认。自建长表单尚未保存的输入，则明确提供继续填写或放弃修改；只有实现对应暂存能力时才能提供暂存退出。

- 统一“已暂存/保存中/失败待重试”的状态，成功反馈建立在实际保存完成上。
- 保存失败提供明确的重试按钮，保留选择和目标；有失败未恢复时，退出需说明输入可能丢失。
- 常规训练确认维持一击完成；覆盖安排、放弃草稿、彻底删除和替换恢复才展示影响确认。
- 返回采用来源页语义：返回训练、返回选择、返回统计，不在不同来源都显示含糊的返回。
- 导入恢复和变更日期范围前处理正在编辑的草稿，避免“记录已恢复，编辑页仍指向旧资料”。

### UX17：手机触控、教学反馈和访问性统一验收

- 网页触控区域以约44×44 CSS px为检查目标；正式Android按项目触控规范验证，不能将px直接等同dp。当前选择器移动端勾选区38px宽应继续检查一手操作。
- 教学图片保留已确认的左右滑动和页码；检查纵向浏览与横向滑图不互相误触。
- 次数输入改为“每组次数”“每组时长（秒）”等完整标签，大字体下不截断动作名、单位和每侧口径。
- 肌肉图不可用时保留文字部位说明，图片加载失败给出重试；给实际用户的提示避免“图层”等实现术语。
- 原型继续清楚标注待审素材；正式教学发布前完成内容审核，不靠收起标签掩盖尚未审校的内容。
- 覆盖小屏、大字体、横屏、读屏、减少动态效果及图片缺失；现有手机尺寸浏览器检查不替代真机验收。

### UX18：高频复用在核心流程稳定后增加

按顺序考虑最近用过、收藏、将一天保存为个人模板、批量应用模板。复用时显示来源和带入的目标，用户可调整；未开始且无历史的目标日才按确认覆盖。随机挑选继续属于原有后续规划。

连续训练卡保留用户要求的天数，可增加本周训练天数作为补充说明；休息日使用中性反馈。热力图、复杂成就和社交不作为下一轮核心任务。

## 4. 建议的执行顺序

### 第一批：上下文与资料保护

先做UX01、UX02、UX04。先补可复现案例与边界，再修改实现：历史日继续、全完成/无任务、四种入口命中草稿、导出/导入共同边界。备份正式媒体部分先落实能力约束和验收方案，不能承诺只改几行即可完成。

### 第二批：让首个计划与首次训练更顺

优先UX03、UX05、UX07、UX09、UX10：缺项定位、单日快捷、动作意图带入、无结果原地自建和当前动作聚焦。保留12已完成的独立选择结构，不把候选重新铺回第三步。

### 第三批：补齐长期使用与全端验证

安排UX06、UX08、UX11—UX17；根据实际使用反馈再做UX18。此处P1之间按依赖拆批，不表示统计、访问性或内容审校可以跳过正式上线门槛。

共同验收方式：按任务记录步骤数、返回次数、是否能找到目标以及误操作；测试者先独立操作，再看说明。步骤数量作为前后对比，不预先宣称提效百分比。继续保存功能编号、边界场景、已测/未测状态和具体复现路径。

## 5. 单独处理原型评审环境

本地预览需要服务进程存活，且使用固定演示日期。评审入口应提供清楚的启动说明、当前演示日期及服务恢复方式；设置系统自启动或公网发布另行确定。调整演示日期不静默移动原有计划/记录。

原型访问连续性、动作教学审校、正式Android实现和备份媒体事务是不同交付项。体验方案评审通过，仍需按照08与11处理内容、工程和设备验证的进入条件。
