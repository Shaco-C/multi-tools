# 居家健身工具 · 产品设计包

设计日期：2026-10-22  
状态：用户已验收交互原型；已全量采集动作源库，进入内容生产及Android开发准备；正式Android健身功能尚未开发。
项目：随身工具箱 / multi-tools，调研时分支为 `main`。

这个工具首先解决一个具体问题：下班在家训练，做完一组后点一下，随时知道自己已经做了几组、还剩几组。动作库帮助用户认识动作和查看教学，训练计划把这些动作安排到具体日期；首页时间轴呈现日程空缺，统计帮助回顾实际训练，恢复参考提醒用户考虑同一肌群的训练间隔。

## 已确认的需求

- 按胸、肩、二头、腿等训练部位浏览内置动作。
- 动作库首页仅展示部位/活动分类，点击分类进入独立动作列表；列表同时呈现肌肉图和姿势图，搜索与筛选放在分类内。
- 动作详情有中文介绍、训练部位、动作步骤；有可靠动图时展示动图，否则左右滑动查看起始到结束的多张图，配姿势名称及步骤页码。
- 内置覆盖大多数常用动作的内容库，并允许用户自己添加动作。
- 按日期范围创建计划，为具体日期多选部位、多选动作，并设置组数和每组次数。
- 进入计划后优先看到今天的训练；每完成一组，点击一次按钮记录。
- 从训练卡片的图片或名称进入动作详情，返回后继续训练。
- 后续考虑按部位、动作数量和目标组次自动挑选动作。
- 首页连续日期时间轴展示每日部位，并明确休息与未安排；两张卡片展示连续训练和今日部位。
- 首页提供基于最近训练记录的一般恢复参考；统计页支持近 7 天、近 30 天及自定义时间范围。
- 统计区分训练天次、完成组数及用户主动填写的实际次数/时长，不将计划目标冒充实际完成。
- **用户已确认器械定位：徒手＋哑铃＋弹力带，兼顾健身房动作。** 训练凳、单杠、固定锚点等不能默认视为用户拥有。
- 原型已经用户验收，动作全量范围扩大到876条来源及原250项覆盖；当前规划内容生产与Android实施步骤，尚未编写正式健身模块。

## 建议的产品形态

工具暂名“居家健身”，底部使用“今日 / 计划 / 动作库 / 统计”四个入口，“管理”放在右上角。默认进入“今日”，顶部时间轴浏览日程，已有训练时能快速继续动作和记组。

首个完整版本包含动作库、手动计划、逐组记录、首页日程与统计、恢复参考、自建动作和独立备份恢复。实际次数/时长可在组明细补填，不增加默认记组步骤。动图允许部分动作具备；**完整中文说明、肌肉图和可辨认的步骤图是内置动作的发布门槛**。静态保持类动作可以采用“进入姿势 / 保持要点 / 退出姿势”的图文组织方式。

12个核心动作＋4个边界样例已用于原型。用户现要求全量建设：**876条源库记录全部进入处理队列，原250项中文候选作为覆盖基线保留**，两组按稳定ID映射去重，不相加成1126个正式动作。最终唯一条目数以映射/合并记录计算；每条来源及原覆盖均须有结果，缺项补齐，不能用小样包冒充全量发布。

## 评审时优先确认的建议

以下是本方案提出的默认建议，尚不代表用户已经逐项批准：

| 议题 | 当前建议 | 原因 |
| --- | --- | --- |
| 工具名称 | 居家健身 | 贴合首要使用场景，库中可浏览健身房动作 |
| 内容范围（已确认） | 全量876条来源＋原250项覆盖映射 | 居家制作优先、兼顾健身房；映射去重而非相加，逐项补齐与审核 |
| 教学形式 | 步骤图必备，动图可选增强 | 不让动图数量拖住计组功能和可靠内容交付 |
| 计量 | 支持次、秒，以及每侧口径 | 覆盖平板支撑和单臂/单腿动作 |
| 完成一组 | 手动确认，默认不逐组填写实际次数 | 保持训练时一击完成的低操作成本 |
| 修改实际次数 | 首版组明细可选补填，展示统计覆盖率 | 只确认组数时，不能把目标次数伪装成实测次数 |
| 部位统计 | 单一统计主归属；教学肌群可以多选 | 避免复合动作被重复累计成多组 |
| 连续训练 | 按自然日，有效力量/有氧记录计入 | 休息日不伪造训练；今日未练暂展示截至昨天的值 |
| 恢复参考 | 最近记录事实＋一般间隔提示 | 不按部位编造固定恢复时间或宣称恢复完成 |
| 素材预算 | 先验证开放/原创路线，商业动图库单独评估 | 免费可浏览与可离线分发是两个不同条件 |
| 恢复数据 | 本工具独立备份，包含用户自建图片 | 换机后计划、记录和自定义动作都可继续使用 |
| 休息倒计时、重量记录 | 后续版本 | 不阻断首版核心闭环 |

## 本次已完成与尚未完成
