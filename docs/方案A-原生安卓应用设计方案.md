# 方案 A：多功能小工具原生安卓应用设计方案

> 文档状态：对照方案，保留供后续比较  
> 编写日期：2026-09-10  
> 当前阶段：只做产品与技术设计、开发环境验证，尚未开始功能开发

## 1. 项目定位

这是一个仅供个人使用、离线优先、可持续扩展的安卓多功能小工具集合。

核心原则：

- 不设计注册、登录、账号和云端服务。
- 所有业务数据默认只保存在当前安卓设备中。
- 首页作为“工具箱”，每个功能是一个相对独立的小工具。
- 新工具应能低成本接入，而不破坏已有工具。
- 第一阶段先完成“电费按用量分摊”，后续再加入历史记录和个人费用趋势。
- 不申请非必要权限；电费工具本身不需要联网权限。

推荐暂定名称：**随身工具箱**。应用名、包名和视觉风格可在开发前再确定。

## 2. 原生安卓路线说明

本方案采用 Kotlin 原生安卓应用：

- 本地数据库稳定，浏览器清理缓存不会影响应用数据。
- 可完全离线使用，无需购买服务器和域名。
- 后续加入本地备份、文件导入导出、通知、小组件等系统能力更自然。
- 可以生成 APK 直接安装在自己的安卓手机上。

这一方案适合更看重安卓系统集成和长期数据可靠性的情况，但开发、构建和真机调试成本高于 Web 前端方案。

## 3. 产品信息架构

```text
随身工具箱
├─ 首页
│  ├─ 电费分摊
│  ├─ 未来工具 A
│  └─ 未来工具 B
├─ 电费分摊
│  ├─ 新建计算
│  ├─ 计算结果
│  ├─ 历史账单
│  └─ 我的费用趋势
└─ 设置
   ├─ 数据备份与恢复（后续）
   ├─ 外观设置（后续）

```

首页用卡片或宫格展示已经启用的工具。每张卡片包含图标、名称和一句简短说明。尚未开发的工具不显示空入口。

工具箱外层只负责展示和选择工具，不提供全局记录或趋势入口。记录、趋势和其他业务页面全部由对应工具自己负责；例如电费分摊内部使用“计算 / 记录 / 趋势”导航，而未来工具可以采用完全不同的内部结构。这样新增工具不会扩大外层导航，也无需统一不同工具的记录格式。

## 4. 第一个工具：电费分摊

### 4.1 使用目标

用户录入某个账期的总电费，以及每个电表的上期、本期读数。应用计算每个电表的用量占比与应分摊金额，并可以保存本次结果。

第一条记录固定代表“我”：

- 始终显示在最前面，并使用“我的电表”标签和明显的视觉标识。
- 不允许被删除；其他电表可以增加、删除和改名。
- 趋势图只统计这条记录对应的应付金额。
- 数据库中使用稳定的 `isOwner` 标记识别，而不是仅依赖显示顺序，避免排序后趋势数据失真。

### 4.2 建议交互流程

1. 从首页点击“电费分摊”。
2. 选择账单月份，输入本期总电费。
3. 输入分摊户数，默认 2 户，最少 1 户。
4. 页面按户数生成对应数量的电表录入卡片。
5. 每张卡片输入上期读数和本期读数；第一张固定为“我的电表”。
6. 输入过程中实时显示各户用量；数据完整后显示占比和金额。
7. 用户检查结果，点击“保存本期记录”。
8. 保存成功后可返回首页、查看历史记录或查看我的费用趋势。

在手机窄屏上，不建议真的横向排成多列输入框。多个电表应纵向排列为卡片，以避免数字输入框过窄；“第 1 列、第 2 列”的业务含义仍然保留为“第 1 户、第 2 户”。

### 4.3 页面结构草图

```text
┌─────────────────────────────┐
│ ← 电费分摊             历史 │
├─────────────────────────────┤
│ 账单月份  [ 2026 年 09 月 ] │
│ 总电费    [       100.00 ]元│
│ 分摊户数  [ － ]  2  [ ＋ ] │
├─────────────────────────────┤
│ ★ 我的电表                  │
│ 上期读数 [ 100 ]            │
│ 本期读数 [ 200 ]            │
│ 用量 100 度 · 50% · 50.00 元│
├─────────────────────────────┤
│ 第 2 户                     │
│ 上期读数 [  50 ]            │
│ 本期读数 [ 150 ]            │
│ 用量 100 度 · 50% · 50.00 元│
├─────────────────────────────┤
│ 总用量 200 度               │
│             [保存本期记录]  │
└─────────────────────────────┘
```

### 4.4 计算规则

设：

- 总电费为 `T`。
- 第 `i` 户上期读数为 `Pᵢ`。
- 第 `i` 户本期读数为 `Cᵢ`。
- 第 `i` 户用量 `Uᵢ = Cᵢ - Pᵢ`。
- 所有户总用量 `U = ΣUᵢ`。

则：

```text
第 i 户占比 = Uᵢ / U
第 i 户应付金额 = T × Uᵢ / U
```

示例：

```text
总电费：100 元
我的电表：200 - 100 = 100 度
第 2 户：150 - 50 = 100 度
总用量：200 度

我的占比：100 / 200 = 50%
第 2 户占比：100 / 200 = 50%
双方应付金额：各 50.00 元
```

### 4.5 金额精度与舍入

金额不能用 `Float` 或 `Double` 直接保存，否则可能产生小数误差。建议：

- 数据库存储金额时统一使用“分”为单位的整数，例如 100.25 元存为 `10025`。
- 读数允许小数时，使用十进制定点数计算并保存其规范化字符串，或按固定精度转成整数。
- 每户金额精确到分。
- 多户分别四舍五入后可能与总电费相差 1～数分，应使用“最大余数法”分配尾差，确保所有户金额相加始终严格等于总电费。
- 最终结果页提示“金额已按分进行尾差调整”，避免用户对 0.01 元差异产生疑问。

### 4.6 输入校验与异常场景

- 户数必须至少为 1，首版建议最多 20 户，避免误操作生成过多输入项。
- 总电费必须大于或等于 0，最多保留两位小数。
- 上期和本期读数均不能为空，且不能为负数。
- 本期读数必须大于或等于上期读数。
- 所有户总用量为 0 时不能计算分摊，页面提示“总用量为 0，无法按比例分摊”。
- 某一户用量为 0 时，其占比与费用均为 0，这是有效数据。
- 户数减少时，如果将删除的卡片中已有输入，应先二次确认，避免误丢数据。
- 同一月份已存在记录时，保存前提示用户选择“覆盖原记录”或“另存为一条记录”。首版建议一个月份只保留一条正式记录，以简化趋势统计。
- 总电费为 0 且总用量大于 0 时，所有户费用为 0，允许保存。
- 电表发生换表或归零时，普通的“本期减上期”规则不再成立；首版先提示用户手工换算成连续读数，后续可增加“换表”模式。

### 4.7 便捷性设计

- 保存上一期账单后，新建下个月账单时，自动将各电表的“本期读数”带入为新的“上期读数”。
- 记住上次使用的户数和其他户名称。
- 数字输入时使用小数数字键盘。
- 计算结果实时更新，但只有完整且合法时才允许保存。
- 离开未保存页面前提示是否放弃更改。
- 历史记录可查看详情；是否允许编辑历史账单可在首版实现时决定，建议允许编辑并重新计算。

## 5. 历史记录与趋势图

### 5.1 历史记录

历史页按月份倒序展示：

```text
2026-09  总电费 100.00 元  我的费用 50.00 元
2026-08  总电费 132.50 元  我的费用 61.20 元
```

点击一条记录可查看当时所有电表的原始读数、用量、占比和分摊金额。保存的是一次完整快照，后续修改默认户名不会影响旧账单。

### 5.2 我的费用趋势

趋势图只读取每条账单中 `isOwner = true` 的金额：

- 横轴：账单月份。
- 纵轴：我的应付金额（元）。
- 默认显示最近 12 个月。
- 图表下方同时显示本月、上月、环比变化和区间平均值。
- 数据不足两个月时显示友好的空状态，而不是空白图表。

首版可以先完成历史列表，在第二阶段加入折线图；数据库设计从一开始就保留趋势所需字段。

## 6. 可扩展的软件结构

已确定从首个版本开始采用“单应用壳、多功能独立模块”的结构，不等待第二个工具出现后再拆分。这样会增加少量初始配置，但可以从一开始约束依赖方向，避免业务代码逐渐堆积在 `app` 模块。

```text
app                       应用入口、工具箱首页、总导航和工具注册
core:common               金额、日期和基础结果类型
core:designsystem         主题与真正通用的 Compose 组件
core:navigation           ToolModule、ToolEntry 等工具接入契约
core:backup               本地备份协调和文件选择基础能力
feature:electricity       电费的计算、记录、趋势与本地数据库
feature:future-tool       后续工具自己的页面、逻辑和数据
```

每个工具实现统一的元信息，例如：

```kotlin
data class ToolEntry(
    val id: String,
    val title: String,
    val description: String,
    val icon: ImageVector,
    val route: String
)
```

首页只读取工具注册表来渲染入口。增加新工具时，创建新的 `feature` 模块并注册一个 `ToolEntry`，不需要修改电费模块的内部代码。

依赖规则固定为：

```text
app → feature:* → core:*
```

- `core` 不得依赖任何 `feature`。
- 不同 `feature` 之间不得直接依赖或读取彼此数据。
- `app` 不理解电费账单等具体业务字段，只负责组装模块和显示入口。
- 每个工具自行决定是否具有计算、记录、趋势或设置页面。
- 首版采用手动工具注册；只有工具数量明显增加后才考虑依赖注入多重绑定。

这是编译期模块化，不需要做复杂的动态插件系统。对于个人应用，动态下载插件会明显增加安全、版本和维护成本，没有实际收益。

## 7. 推荐技术方案

| 范围 | 推荐选择 | 原因 |
|---|---|---|
| 开发语言 | Kotlin | 安卓官方主流语言，空安全，适合长期维护 |
| 界面 | Jetpack Compose + Material 3 | 声明式界面，开发效率高，适配现代安卓 |
| 架构 | 单 Activity + MVVM + 分层结构 | 足够清晰，又避免个人项目过度设计 |
| 页面导航 | Navigation Compose | 工具模块之间路由明确 |
| 本地数据库 | Room（SQLite） | 适合账单、明细和趋势查询，支持数据库迁移 |
| 简单设置 | DataStore | 保存主题、最近户数等轻量偏好 |
| 异步处理 | Kotlin Coroutines + Flow | 与 Room、Compose 配合自然 |
| 依赖注入 | 首版手动注入 | 当前规模无需立即引入 Hilt，可在工具增多后再加 |
| 图表 | Compose Canvas 自绘简单折线图，或后续评估图表库 | 趋势图需求简单，减少第三方依赖和包体积 |
| 构建 | Gradle Kotlin DSL + Version Catalog | 依赖版本集中、便于升级 |
| 最低安卓版本 | 建议 Android 8.0（API 26） | 覆盖足够广，也能降低兼容复杂度 |
| 目标版本 | 创建项目时采用已安装 SDK 支持的最新稳定版 | 满足现代系统要求，具体值以开发时工具链为准 |

应用应显式避免声明 `INTERNET` 权限。没有网络权限能更直观地证明首版不会上传数据。

## 8. 本地数据模型

电费模块拥有独立的 Room 数据库文件，例如 `electricity.db`；未来其他工具如果需要结构化数据，使用自己的数据库文件和迁移，不建立一个不断膨胀的全局业务数据库。电费数据库包含以下两张主要表。

### `electricity_bill`：账单主表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键 |
| `billingMonth` | String | `YYYY-MM`，用于排序和趋势 |
| `totalAmountCents` | Long | 本期总电费，单位分 |
| `totalUsage` | String | 本期总用量的十进制规范值 |
| `createdAt` | Long | 创建时间戳 |
| `updatedAt` | Long | 更新时间戳 |
| `note` | String? | 可选备注 |

### `electricity_share`：每户分摊明细

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键 |
| `billId` | Long | 所属账单外键，删除账单时级联删除 |
| `position` | Int | 当时显示顺序 |
| `label` | String | “我的电表”或其他户名称的历史快照 |
| `isOwner` | Boolean | 是否为本人，账单内必须且只能有一条为 true |
| `previousReading` | String | 上期读数的精确十进制值 |
| `currentReading` | String | 本期读数的精确十进制值 |
| `usage` | String | 本期用量快照 |
| `allocatedAmountCents` | Long | 分摊金额，单位分 |

占比可以由 `usage / totalUsage` 重新计算，不必重复保存。保存账单和所有明细时必须使用一个数据库事务，避免只保存了一半。

数据库从第一个版本开始设置明确版本号并编写迁移；发布后不能使用破坏式迁移清空用户数据。应用级备份由 `core:backup` 协调，但每个工具通过统一的 `BackupProvider` 接口自行导出和恢复自己的数据，备份层不理解具体业务字段。

## 9. 隐私、备份与数据安全

- 数据仅写入应用私有目录，其他普通应用无法直接读取。
- 首版不接入统计 SDK、广告 SDK、登录 SDK，也不申请联网权限。
- 卸载应用会删除应用私有数据，应在设置页明确提醒。
- 后续建议提供用户主动触发的本地 JSON 导出与导入，用于换手机和备份。
- 导出应使用安卓系统文件选择器，由用户决定文件保存位置；应用不自行上传。
- 导入前校验文件版本与内容，并在覆盖现有数据前确认。
- 如果数据非常在意，可进一步支持加密备份；个人电费数据的首版无需引入数据库加密复杂度。

## 10. 测试重点

### 计算单元测试

- 题述的 100 元、两户各 100 度，结果应为各 50.00 元。
- 三户比例无法整除时，尾差分配后金额之和必须等于总金额。
- 某户用量为 0。
- 总用量为 0。
- 小数读数和超大读数。
- 总金额为 0。
- 本期读数小于上期读数时返回校验错误。

### 数据测试

- 保存账单与明细的事务完整性。
- 查询某月详情。
- 按月份排序。
- 趋势查询只返回 `isOwner = true` 的金额。
- 数据库升级后旧记录不丢失。

### 界面测试

- 户数增减正确生成和删除卡片。
- 旋转屏幕或应用进入后台后，未保存输入不应意外消失。
- 键盘不会遮挡当前输入项和保存按钮。
- 深色模式下文字和错误提示清晰可读。

## 11. 开发阶段规划

### 阶段 0：工程初始化

- 安装并配置 Android Studio、Android SDK、ADB。
- 使用 JDK 17 创建 Kotlin + Compose 工程。
- 建立模块、主题、首页和自动化测试骨架。

### 阶段 1：可用的电费计算 MVP

- 工具箱首页。
- 电费录入、户数动态增减、输入校验。
- 精确计算、尾差处理、结果展示。
- 暂存页面状态与计算单元测试。

### 阶段 2：本地持久化

- Room 数据库。
- 保存、查看、编辑或删除历史账单。
- 自动带入上一期电表读数。

### 阶段 3：个人趋势与体验完善

- 我的费用趋势图和汇总指标。
- 空状态、深色模式、无障碍和更多测试。
- 本地备份与恢复。

### 阶段 4：新增其他工具

- 根据实际生活需求逐个增加独立 `feature` 模块。
- 当公共组件确实重复出现时再抽取到 `core`，避免提前过度抽象。

### 环境结论

**当前系统具备开始编写普通 Kotlin/JVM 代码的基础，但暂时不能完整构建、安装和调试安卓应用。** 主要缺口是 Android Studio/Android SDK/ADB；JDK 不需要重新下载，只需让 Android Studio 或项目构建使用现有 JDK 17。

后续开发前建议完成：

1. 安装最新稳定版 Android Studio。
2. 通过 SDK Manager 安装一个稳定的 Android SDK Platform、对应 Build-Tools、Platform-Tools 和 Emulator。
3. 将 Gradle JDK 指向 `E:\Programs\jdk\jdk-17.0.18`，不要继续使用当前默认 JDK 8。
4. 创建项目后使用项目自带的 `gradlew.bat`，不要求系统全局安装 Gradle。
5. 创建至少一个模拟器，或开启安卓真机的开发者选项与 USB 调试。
6. 用 `gradlew.bat test` 验证单元测试，用 `gradlew.bat assembleDebug` 验证能生成调试 APK，再用 ADB/Android Studio 安装运行。

是否采用最新目标 SDK、Compose 和依赖版本，应在真正初始化项目当天依据 Android 官方稳定版本确定，不在设计文档中硬编码一个容易过时的版本号。

## 13. 开发前建议确认的少量产品决定

这些问题不影响当前总体架构，可在正式开发时再确定：

- 应用正式名称与包名。
- “户数”是否等于“电表数”；本文暂按一户一个电表处理。
- 同一个月份是否允许保存多张账单；本文首选每月一张正式记录。
- 其他户是否需要自定义名称；本文建议支持，例如“隔壁”“二楼”。
- 首版是否必须包含历史记录，还是先交付只计算不保存的最小版本。考虑到本项目明确需要本地数据和趋势，建议首个可安装版本就包含保存与历史记录。

## 14. 验收标准（首个完整版本）

- 应用无登录、无云端依赖、无联网权限，断网可完整使用。
- 首页可以进入电费分摊工具，并为后续工具保留清晰入口机制。
- 用户可设置户数并录入每户上下期读数与总电费。
- 计算结果准确到分，所有户金额之和严格等于总电费。
- 第一户固定为本人，不能误删，趋势数据始终来自本人记录。
- 账单能可靠保存在手机本地，重启应用后仍可查看。
- 可查看按月份排序的历史记录和最近 12 个月的个人费用趋势。
- 关键计算、数据库查询和主要交互具备自动化测试。
